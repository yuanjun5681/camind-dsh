Camind 平台架构

现场顾问与云端支持形成问题闭环，研发 Agent 经受限流水线发布测试版；Camind 服务管理租户与业务，既有 NX 工作台集群通过队列与路由分配资源。

架构为目标示意，不代表能力已验收。箭头表示业务关系，不代表开放公网入站连接；窄屏可在图内横向滚动。

平台与集群不重复调度

Camind 管理客户、授权、业务作业、用量与交付；NX 工作台通过既有队列和路由管理执行资源。两端保留业务作业 ID、集群任务 ID 和输入指纹的关联，断线后查询原任务，取消须取得执行端确认。

支持与研发不是同一权限

顾问经用户确认上传范围后提交反馈，支持 Agent 答疑并按需转研发。工单、证据授权和验收记录由服务持久保存；进化 Agent 经受限流水线发布测试版，不能自行批准现场启用。

执行和终端边界

  • 方案、交付、传程序和启动加工分别授权，设备端执行前复核实时条件。
  • ClawSynapse 是候选实现，认证、TLS、持久化、隔离和附件边界须通过验证后才能用于生产设备执行。
  • ESP32 等只读终端为可选专项，不作为首期必验项，也不承担安全控制。
  • 一个站点验收通过，不自动授权其他站点启用；租户隔离不因已有 NX 集群而自动成立。
