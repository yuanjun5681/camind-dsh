# PRT 完整 3D 渲染：数据需求与实现流程

本文说明如何将 NX `.prt` 零件模型显示在 Camind 界面中，以及 NX 工作台需要提供哪些数据。本文包含方案与 NX Windows 工作台接口源码核查（2026-10-10）。工作台已有几何包导出实现；Camind 本仓尚未接入该管线和完整模型预览。几何包已对一个示例零件完成远端导出和数据校验（§13）；这不代表所有接口、模型或浏览器交互都已验收。NX 功能及读件实测见 [西门子 NX 概览](siemens-nx-overview.md)。

## 1. 目标与范围

第一步目标是在浏览器中准确显示零件的完整外形，支持旋转、缩放、平移和适配视图。

进一步可以支持：

- 点击或高亮一个面。
- 查看该面的类型、位置和法线。
- 标注孔、加工区域和坐标系。
- 将选中的面传回 NX，用于后续工艺操作。

这些能力需要的数据不同，应分开处理。显示模型不等于编辑 CAD，也不等于材料去除仿真。

## 2. 为什么不能仅用 `/cam_survey` 摘要渲染完整模型

本次 `/cam_survey` 默认调用已返回实体数量、包围盒、面类型统计、部分平面和圆柱面的位置与尺寸、孔识别结果及 `face_tags`；没有返回显示网格或完整面边界。这是对该端点响应的核实，不是说整个工作台缺少这些数据：独立几何包管线已提供显示网格、顶点法线、离散边线与 FID 映射（§10、§13）。

以下是摘要表达能力的限制，不是工作台待开发清单：

- 包围盒只描述外部范围，不描述零件轮廓、槽或孔。
- 即使补充平面法线，位置、法线和宽高也不能确定实际裁剪边界；本次摘要没有返回法线向量。
- 即使已知圆柱面的直径与轴线，也不能仅据此确定整圆、部分圆弧或被其他面裁剪后的形状；本次摘要主要给出位置和是否竖直的判断。
- 面标识只是引用，不包含该面的几何。
- 分类和筛选后的面列表不一定覆盖所有面。

增加摘要法线也不能替代完整形状。浏览器应使用已导出的网格，不凭摘要重新构造零件。本文已验证显示用的离散数据，没有验证精确曲面边界或完整 CAD 拓扑导出。

## 3. 推荐路线：NX 提取显示网格

```text
上传 PRT
    ↓
NX 工作台打开模型并选定导出范围
    ├─ 读取几何事实 → 特征分析、标注与面属性
    └─ 对实体表面进行三角化
              ↓
       导出网格与必要元数据
              ↓
       Camind 回收文件并提供预览
              ↓
       浏览器渲染完整零件
```

PRT 由 NX 解析，浏览器接收适合显示的网格，而不是自行解析 NX 的专有二进制文件。应优先使用 NX 的几何与三角化能力，避免在前端重新实现 CAD 几何内核。

网格是模型表面的近似表示。正确处理全部目标实体、曲面和裁剪边界，并使用合适的三角化精度，才能得到外形完整的预览。

## 4. 基础显示必须提供的信息

| 信息 | 用途与要求 |
|---|---|
| 顶点位置 | 每个顶点的 X/Y/Z 坐标 |
| 三角形连接关系 | 顶点索引，或无索引格式中按三点组成三角形的明确约定 |
| 单位 | 明确毫米、英寸或其他单位；不能由尺寸数值猜测 |
| 坐标约定 | 明确模型坐标系、轴方向、左右手系及转换方式 |
| 实体与节点变换 | 单零件可用统一坐标；装配必须正确应用实例的位置、旋转与缩放 |
| 导出范围 | 是整个零件、可见实体、指定实体，还是整个装配；必须明确 |
| 完整性状态 | 是否有实体或面导出失败、是否截断；部分结果不能静默标为完整 |

基础渲染还应有以下配套信息：

| 信息 | 用途 |
|---|---|
| 顶点或面法线 | 正确光照和曲面外观；缺失时可计算，但可能损失 CAD 的光顺与硬边效果 |
| 包围盒 | 适配视图、设置相机与近远裁剪面；也可从网格计算 |
| 颜色与材质 | 可使用统一默认材质；需要保留 NX 外观时再导出 |
| 三角化参数 | 记录弦差、角度等精度设置，说明模型显示误差 |
| 顶点、三角形及实体数量 | 校验规模、排查缺失、控制加载资源 |

只看外形不要求导出精确曲面方程、拓扑或原始建模历史。

### 曲面、边界与硬边

三角化应由 NX 处理裁剪后的面边界，保留孔口、槽、外轮廓和相邻面的连续关系。

尖锐边界两侧可能需要不同法线，因此同一位置的顶点可以重复。不要为了减少顶点数量而盲目合并，否则会把应当清晰的棱边显示成光滑曲面。

## 5. 选面与属性查询需要额外信息

### 网格与 NX 面的映射

需要保留：

**三角形 → 包内面序号 → FID 与所属实体 → 标记副本中的 NX 面。**

可以按面划分网格，也可以为一个网格提供三角形范围或三角形到面的映射。具体表示按导出器和渲染器选择，不要求每个三角形重复存一份完整面属性。

只有 `face_tags` 不够：必须知道画面中被点击的三角形对应哪个面。现有几何包使用「三角形所属面序号 → 面表 FID → 标记副本的面属性」完成映射，不需要把运行时 Tag 当作持久 ID。

### 面属性

| 信息 | 用途 |
|---|---|
| 面引用 | 关联 NX 原始面 |
| 面类型 | 平面、圆柱面、圆锥面、自由曲面等 |
| 所属实体 | 区分多个实体或装配实例 |
| 包围盒或代表点 | 定位与显示属性 |
| 平面法线 | 判断平面方向 |
| 圆柱／圆锥轴线与参数 | 显示轴向、直径及相关几何 |
| 曲面指定点的法线 | 查询曲面局部方向 |

**曲面没有统一的法线。** 若需要精确法线，应将点击位置转换回 NX 坐标，由工作台在对应面上求值；还需约定最近点投影、容差和错误处理。网格插值法线只适合显示或近似查询，不能冒充精确 CAD 法线。

### Tag 与模型版本

NX Tag 可用于当前模型上下文中的引用，但不能默认是长期稳定 ID。

面映射必须绑定模型版本和有效的 NX 上下文。可用源文件哈希标记版本，但哈希本身不能保证 Tag 在重新打开后不变。源模型修改后应重新验证或生成包。重新加载同一份未修改的标记副本时，可复用包和 FID，但必须重新解析 NX 运行时对象，不能复用旧 Tag。

工作台已有 `CAMIND_FID` 面属性机制，写入标记副本并用于重新解析面。FID 的复用依赖保存并继续使用同一标记副本；从未标记原件重新准备可能重新编号。选择必须绑定包版本／面表指纹，不能只保存 FID，也不能只用面数和 FID 集合哈希判断是否仍是同一批面。

## 6. 数据格式选择

| 格式 | 适用性 | 注意事项 |
|---|---|---|
| `camind-geom` v1 | 本项目优先接入的现有格式，提供两档网格、法线、面映射和边线 | 需实现浏览器读端并遵循既有校验契约 |
| GLB / glTF | 通用交换的候选，支持网格、法线、材质、节点和变换 | NX 能否直接导出未核实；转换时需保留面映射 |
| STL | 简单外形预览的备选 | 通常不保留单位、材质、装配结构和 NX 面映射，需配套元数据 |
| STEP | 交换精确 CAD 几何 | 不是直接用于浏览器显示的网格，仍需要几何解析与三角化 |
| 其他自定义网格文件 | 只有现有格式不能满足实际需求时再考虑 | 不为本项目预览重复制定一套导出格式 |

源码核查后，优先复用已有 `camind-geom` v1 几何包（见 §10），直接读取 CMGM 网格和 CMGE 边线；无需为了预览再开发一个 NX GLB 导出器。GLB/glTF 可作为以后通用交换格式，转换时必须保留面映射。

glTF 使用米作为长度单位。若源零件为毫米，应在导出或节点变换中显式转换，并记录转换关系，保证点击坐标可以准确转换回 NX。不要为改善初始视图而永久改变模型尺寸。

大型网格宜用二进制文件传输，不宜把全部顶点和三角形放进读件摘要或 Agent 对话。

## 7. 工作台与界面的职责

### NX 工作台

- 打开指定 PRT，读取单位和坐标信息。
- 确定导出范围，区分零件实体与辅助实体；当前几何包不支持装配实例。
- 使用 NX 几何能力三角化目标表面。
- 输出显示文件、完整性状态及必要元数据。
- 输出既有网格到 FID 的面映射。
- 导出失败时返回明确原因，不把部分模型标成完整。

显示导出不应创建 CAM 设置、修改源文件或生成刀路。现有几何包第一步会写 FID 并另存标记副本，属于写件操作，不能宣称整条管线完全只读；后续步骤读取标记副本并写包文件。准备入口还会处理同名已打开件，接入时须避免关闭用户有未保存修改的模型，宜使用受管工作副本或隔离会话。

### Camind Host

- 复用现有上传与长任务调用流程。
- 回收显示文件并验证传输完整性。
- 以会话隔离的只读预览路由提供文件。
- 限制文件大小、路径和资源访问，保留现有防越界措施。
- 保存源文件版本与预览产物的关联，避免显示旧模型。

当前项目已经有上传、长任务、文件回收和预览服务，可复用这些能力编排 §10 的既有几何包端点。五步必须在同一工作台顺序执行，使用独立包目录；只有最后清单提交成功后才能向前端发布，不能把第一步成功当作整包成功。

### 浏览器

- 加载显示网格，设置相机、光照、旋转、缩放和平移。
- 展示加载中、失败、空模型和部分导出等状态。
- 按模型坐标约定正确显示，必要时转换为渲染器坐标。
- 若有映射，支持拾取、高亮与面属性查询。
- 对过大的模型采取资源限制，不让浏览器无界分配内存。
- 卸载时释放网格、材质和 GPU 资源。

当前 NC 刀路查看器显示加工轨迹，并不是零件实体查看器。完整模型预览可以接入现有内容预览入口，但不应把轨迹数据当作实体网格。

## 9. 当前结论

新版 `/cam_survey` 已返回部分面的 Tag 和更丰富的几何摘要，但本次实测没有返回显示网格、法线向量或完整拓扑。

源码核查发现工作台已具备**两档网格、顶点法线、面映射、边线和包校验**管线。下一步应优先接入既有几何包，不再从摘要拼模型，也不重复建设网格导出。

已完成源码核查、示例几何包导出与数据校验；尚未实现浏览器渲染和点击到 NX 的交互往返。执行中生成标记副本并产生测试副本的会话修改标记，详见 §13。完整模型显示不能替代加工仿真与上机安全检查。

## 10. NX Windows 既有接口核查

### 核查范围与依据

本节接口清单来自相邻 `CAM-Agent` 仓库源码；远端实测的范围和结果单独列在 §13、§14，不将源码存在等同于全部端点可用。以下路径均相对该仓库：

- `nx_windows_agent/nx_worker/endpoint_registry.py`：队列端点、处理器与风险标记。
- `nx_windows_agent/nx_worker/handlers/geometry_pack.py`：几何包五步管线与按 FID 加工。
- `nx_windows_agent/nx_worker/handlers/geompack_format.py`：格式读写与校验。
- `nx_windows_agent/nx_worker/handlers/inspection.py`：读件、体清单、旧网格导出、截图。
- `nx_windows_agent/nx_worker/handlers/inspection_probes/geometry.py`：面摘要与法线探针。
- `Doc/几何包格式规范_v1.md`：现有几何包契约正本。
- `geom_service/server.py`、`geom_service/app.py`：上层几何服务路由与 FID 属性查询。

格式以 [CAM-Agent 几何包正本](../../CAM-Agent/Doc/几何包格式规范_v1.md) 为准，下文只是接入摘要，不复制维护第二套格式规范。完整调用参考见 [API](../../CAM-Agent/nx_windows_agent/docs/API.md) 和 [客户端指南](../../CAM-Agent/nx_windows_agent/docs/CLIENT_GUIDE.md)。

### 10.1 完整模型与选面：优先复用几何包

| 顺序／接口 | 主要参数 | 输出与作用 |
|---|---|---|
| 1. `/cam_geompack_open` | `prt`、`out_dir`、`part_sha256`；可选 `fid_property`、`pipeline_version` | 校验零件，写入／复用 FID，另存标记副本，生成面表；返回副本信息、面数、原点偏移等 |
| 2. `/cam_geompack_facet` | `prt` 标记副本、`out_dir`、`lod: coarse`；可选 `chord_tol_mm`、`angle_tol_deg` | 粗档网格、顶点法线、面到网格范围的映射 |
| 3. `/cam_geompack_facet` | 同上，`lod: fine` | 细档网格；返回实际公差、片数和放宽重试状态 |
| 4. `/cam_geompack_edges` | `prt` 标记副本、`out_dir`；可选 `chord_tol_mm` | 离散边线和相邻面序号，返回采样失败和 B-rep 边数核对信息 |
| 5. `/cam_geompack_manifest` | `prt`、`out_dir`、`part_sha256`；可选 `part_filename` | 读回校验整包、细档面积自检，最后写入清单作为提交点 |

包包含：

- `manifest.json`：单位、原点偏移、相对包围盒、文件大小与 SHA256、版本、告警及可选体表。
- `faces.json`：FID、所属体、面类型、颜色、图层、面积、相对包围盒等；文件以 gzip 编码。
- `mesh_coarse.bin`、`mesh_fine.bin`：gzip 编码的 CMGM，包含顶点、法线、索引与每面网格范围。
- `edges.bin`：gzip 编码的 CMGE，包含边折线和两侧面序号。
- 标记副本 PRT：留在工作台侧，用于后续 FID 解析；不作为浏览器显示文件下发。

**现有边界：**

- v1 只支持毫米零件，拒绝带子组件的装配。
- 当前选择可见实体，排除隐藏体、片体和 CAM 辅助体。因此「完整」是对入选实体而言，不是文件里的全部对象。
- 包坐标 = 零件绝对坐标 − `origin_offset`；回传点击位置时必须加回偏移。
- 默认粗档公差为 0.05 mm／15°，细档为 0.01 mm／5°；以清单实际参数为准，失败后可能放宽重试。
- 边采样失败可能退化为端点直线，甚至跳过，必须检查采样告警和边数差异；边线不是无条件精确的 B-rep。
- 体表编号、面表编号是包内引用，不是装配实例 ID。边表也没有长期持久边 ID，不能用其下标跨包定位原始 NX 边。
- 面积普通偏差是告警，粗差会拒绝提交。接入端仍需执行格式、哈希、数量、索引和资源限额校验。

### 10.2 可复用的查询与辅助接口

| 接口 | 现有用途 | 接入注意 |
|---|---|---|
| `/cam_survey` | 工艺几何摘要与孔候选 | 不提供完整显示网格 |
| `/cam_part_bodies` | 体清单；`all_bodies: true` 可读图层、颜色、隐藏状态、体积等 | 基础列举可复用；不要混入 `overlap_pairs`、`subtract_pairs`、`fill_probe` 等创建临时几何的实验参数；编号须与包内 body 映射 |
| `/cam_face_dump` | 遍历实体面并读类型、范围；`normals: true` 尝试非平面参数域中点法线；`points` 最多 200 个，查询点与实体的包含关系 | 当前面行是枚举序号 `i`，不是 FID；法线与解析参数尽力返回，失败写 `_diag`；不能充当任意选中面任意点的精确求值接口 |
| `/cam_face_normal_probe`、`/cam_facet_normals` | 法线 API 与三角化能力诊断 | 是探针，不是面向用户的通用法线查询服务 |
| `/cam_facet_dump` | 返回 JSON 顶点和索引的旧显示网格 | 无逐面映射，法线交客户端计算；有 `max_facets` 上限与 `facet_cap_hit`，不优先用于完整模型与选面 |
| `/cam_export_views` | NX 界面截图／视图导出 | 需要有界面的 NX，不等于浏览器交互相机控制 |
| `/ele_session_state` | 查询已打开件等会话信息 | 可辅助诊断，但不是统一的选择、视图、模型版本状态接口 |
| `/cam_face_mill_by_fids` | 在标记副本上按 `faces: [{fid, role}]` 创建面铣并出 NC | 已有 FID → NX 面的执行链，但这是高风险写件、验收通道，不是普通选择／高亮接口；预览阶段不得调用 |

注册表中的 `read_only` 不等于不会影响会话。还须检查 `mutates_session`、`writes_part`、可选参数与处理器行为，不能把名称带 `probe` 的接口一概当作安全读操作。

## 11. 自然语言交互还需要哪些接口

以下区分**已有能力的接入**与**需要扩展的能力**，不是全部都要新建 NX URL。2026-10-10 二次复核还检查了 CAM-Agent 上层 `geom_service`，发现已有 FID 属性预校验接口；基础属性查询不应继续列为工作台缺失。专用探针或工序创建接口不能直接当作通用交互接口。

### 11.1 应先在浏览器／Camind 实现的接口

| 能力 | 输入／状态 | 作用 |
|---|---|---|
| 预览状态查询 | 会话、模型包版本 | 返回当前模型、视角、显隐、选择、选择过滤器、单位和坐标约定 |
| 相机控制 | 标准视图或相机参数、适配对象 | 实现「俯视」「放大这个孔」「适配整个零件」；不需要往返 NX |
| 显隐与外观 | 包内体／面引用、显示／隐藏／独显／透明度 | 控制浏览器模型，默认不修改 NX 显示状态 |
| 选择与高亮 | 包版本、body／FID／包内 edge 引用、替换／追加／移除／清空 | 让 Agent 展示候选并保持当前选择；高亮不等于创建工序 |
| 点击结果与临时编号 | 拾取引用、包坐标、候选列表 | 点击提供对象，语言表达意图；「第 2 个」只在当前候选集内有效 |

模型数据来自几何包。相机、透明度和高亮属于浏览器交互状态，无需为每个动作新增 NX Windows 端点。状态服务应让 Agent 能读回操作结果，并拒绝旧包引用。

### 11.2 已有查询能力与按需扩展的 NX 能力

本节是交互功能路线，不是完整渲染的前置条件。只做模型显示、按面拾取及包内基础属性查询，不需要先补齐下列精确查询、测量、原生 NX 同步或装配能力。

| 优先级 | 能力 | 最小输入与输出 | 当前缺口 |
|---|---|---|---|
| 已有，先接入 | FID 基础属性与有效性 | 包版本、FID → 是否存在、面类型、面积；包面表还提供所属体、范围等 | 上层几何服务已有 `POST /api/geometry/parts/{sha}/packages/{pv}/faces/resolve`，也可直接查已校验面表；不是 NX Windows proxy URL，不需要重做 |
| P1（需要精确属性时） | FID 精确几何查询 | 标记副本／包版本、FID → 轴线、半径、解析参数等 | 现有 FID 解析可复用，但缺统一结构化查询；不能从基础面表推出全部精确几何 |
| P1（需要精确求值时） | 面上点求值／投影 | FID、零件坐标点或 UV、容差 → 面上点、UV、定向法线、投影距离 | 中点法线接口在当前部署上未能返回解析法线，相关 UF 方法缺失；需验证可用 NX API 路线，不能只增加一个 URL；裁剪域外必须明确失败或投影结果 |
| P1（需要精确测量时） | 精确测量产品化 | 对象引用、测量种类、坐标系 → 距离／角度／半径等数值、单位和定义 | 已有 `/cam_face_truth_probe` 用 MeasureManager 测点到实体／候选面的最小距离，但会建临时点并撤销，且不按 FID 寻址；可复用测量实现，不当作通用测量接口；网格测量标为近似 |
| P1（需选边／点时） | 边与顶点引用、属性、邻接查询 | FID 与边／顶点引用 → 曲线类型、端点、长度、相邻面；验证原始 NX 引用 | CMGE 只有离散线与相邻面，没有持久边／顶点映射；不能直接拿显示边下标操作 NX |
| P2（需同步原生 NX 时） | NX 选择／高亮／视图／显隐控制与读回 | 有效引用、操作类型 → 实际状态与失败对象 | 当前未找到统一接口；仅需浏览器操作时不补，要求控制 Windows NX 窗口时才补，并标明显示依赖和会话影响 |
| P2（支持装配时） | 装配树与实例几何导出 | 装配文件 → 实例路径、原型引用、实例变换、加载状态与映射 | 当前几何包拒绝装配；不能仅增加组件名而不处理 occurrence／prototype 与实例坐标 |

自然语言筛选优先利用既有面表、体表和几何查询，在 Host 做确定性的筛选。只有缺少准确几何属性时才补工作台查询能力，不必先建一个接受任意自然语言的 NX 大接口。

### 11.3 共用契约与执行纪律

- **上下文绑定**：对象引用包含模型／包版本及引用类型；查询和操作前验证有效性。FID 仅在对应标记副本内解释。
- **坐标明确**：空间点、模型顶点、面上点分开表达，声明包坐标／零件坐标／MCS 以及单位。
- **歧义处理**：多个对象满足「上面的孔」等描述时，返回候选并高亮，让用户确认；不自动猜测。
- **结果可读回**：返回实际匹配对象、执行结果与逐项失败，不只返回泛化的成功消息。
- **控制状态与修改分离**：选择、高亮不隐式建几何、算刀路或保存文件。真正的修改需工作副本、确认、失败恢复与明确保存语义。
- **长任务纪律**：既有工作台管线通过 `/submit` + `/poll` 编排，文件通过现有上传／下载通道传输。超时不代表任务未执行，不能盲目重复提交写件步骤。

## 12. 推荐接入顺序

1. 复用 §13 已通过的示例验收结果；换零件类型、导出版本或范围后，再用受管副本做针对性核对，不要求每次重复完整验收。

5. 只有用户需要原生 NX 同步或装配操作时，才补显示控制或装配能力。

## 14. 交互接口缺口二次复核（2026-10-10）
