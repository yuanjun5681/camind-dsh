# Camind 桌面场景 1 手测结果与界面优化方案

> 历史测试记录：前文反映 2026-10-13 的界面与建议，保留原观察；不作为当前布局规范。随后回归也按日期阅读。2026-10-14 的有效交互见 [工作台设计](cam-workbench-interaction-design.md) 与 [手测清单](ui-manual-test-cam.md)。


2026 年 10 月 13 日，使用 `sh ./scripts/desktop.sh` 启动本项目桌面端，按 [手测场景 1](ui-manual-test-cam.md) 新建 CAM 加工会话，选择指定的 PRT 和 DWG，发送原文接件审图请求，并完整重启核对恢复行为。

结论：正式接件与部分数据护栏已经可用，桌面工作台的布局、视觉、状态引导和图纸可视化尚不能通过交互验收。应优先改成一个持续存在的模型工作区，按任务状态展开确认工作区，辅助功能停靠侧边；继续增加内容 TAB 无法解决当前问题。

本次为测试与优化建议，未修改功能代码或现有目标设计。三维生成、方案执行和交付不属于场景 1 的通过范围。材料、版本对应与装夹没有现场确认依据，测试保留未决，没有编造答案来走通流程。

## 需要优先解决的问题

### 任务范围与阶段不匹配

用户仅要求“先接件审图”，正式 `goal` 却被写成“编制并交付 NC 工艺包”。顶栏统称“阻塞”，又把未绑定机床、工序表为空与审图缺项混在一起，容易让用户误以为当前请求失败。

应分别保存任务最终目标与本次工作范围。对于本次请求，显示“审图已整理，待确认”，只突出材料冲突、图纸范围等当前问题。尚未开始规划时，机床和工序为空属于后续待办；它们依然可以阻止执行，但无需占据当前审图首屏。Agent 不能自行把审图扩为 NC 交付目标。

### 界面缺少统一组件与视觉层级

确认向导、工序页、图纸标注使用裸 `input / select / button`，与已做样式的模型工具栏、官方 composer 不一致。页面有大量无组织留白，标题与长问题正文占据主视区，错误提示中直接暴露 `material / stock / datum / fixture`。

应统一桌面可用的主题 token、Button、Field、状态徽章和面板容器。桌面不能仅依赖 `/camind` 才激活的 foundation。正文建议 14px、辅助信息 12–13px，字段与操作左对齐，使用固定间距体系。用户文案改为材料、毛坯、基准、装夹；显示文字、图标和颜色共同表达状态。

模型预览的深色空态中，“确认并生成三维预览”按钮当前呈深色低对比度，需使用与画布表面匹配的按钮样式。

### 多层 TAB 把对象与流程拆散

当前存在会话工作台/对话/轨迹/预览、工作台模型/图纸/向导/工序、左面板输入/交付物/加工三层切换。用户须记住内容在哪一层，切换确认又把模型挤出主视区。

按本次用户要求，工作台内取消这些业务页面 TAB。会话级对话/轨迹仍保留历史与调试入口；工作台内用画布视图工具切换模型、图纸或并排，用侧边按钮打开确认、工序、执行与交付面板。大型工序表可临时展开，再关闭恢复同一画布。

### 确认向导缺少问题归并

通用字段与 Agent 问题围绕材料、毛坯、基准装夹、文件对应重复提问；系统连接和几何导出也变成自由文本答题。“暂不确定”后重新挂载，文件配对复选框仍未勾选，但“记录回答”已启用，状态表达容易误导。

按稳定字段和对象归并问题，一个回答更新关联项并展示影响。材料冲突卡并列“当前图纸”和“历史经验”，明确历史经验仅供参考；不要把测试历史值变成本单默认事实。每张问题卡显示问题、依据、候选、回答方式、后果和保存状态。系统任务提供重试、连接检查或生成预览动作，用户无需回答“几何包为什么未生成”。

### 图纸可视化与面板尺寸失效

默认状态出现空白图纸、标注面板裁切和横向滚动；收起左面板后标注才可读。标注选择展示完整 JSON、原始 CAD 格式控制串，612 条记录没有面向审图的搜索与归类。

现有 `DwgPane` 使用固定 700×1000 内容和内部 240px 检视栏，外层又有画布与左右面板，缺少统一尺寸约束。转换 SVG 的 `viewBox` 与部分路径坐标也存在明显范围差异，是空白预览的调查线索，尚未确认完整根因。

先核实实际可见实体、布局和边界，提供适配、平移、缩放、图层与布局选择；预览没有可见内容时应明确报错并给替代查看入口。标注列表使用搜索、分类、分页或虚拟列表，显示清洗后的文字与来源标签；原始句柄与 JSON 收入详情。语义读取成功与可视化成功分别显示。

### 底部浮层需要统一空间管理

代码已经使用固定浮层并测量高度设置底部留白，因此不能将问题简单归因为“composer 没有 fixed”。生成中/结束后高度差异、任务条、状态栏和多重滚动容器共同影响可用空间。生成中的公开回复还原样显示 Markdown 表格和标题符号，完成后“任务 5 已完成”紧邻“R1 阻塞”，容易混淆回合行动与正式加工状态。

本次最大化窗口中，向导滚到末尾后仍可见最后的问题；没有复现所有页面底部都完全遮挡。用户附件中的遮挡仍应作为回归用例，结合原窗口尺寸进一步验收。

使用一个会话区域内的底部容器管理 composer、当前输出、审批、附件、引用和状态条。容器测量自身真实高度；画布及侧边滚动内容共享安全区，模型工具不进入被覆盖区域。生成时显示简短公开状态及最新产出入口，长文进入对话；结束恢复 composer。原生任务条标明“本轮行动完成”，正式任务阶段始终独立显示。

## 建议的单工作区布局

```text
┌ 会话导航 ┬ 件号  R1  审图待确认  待确认数量        [继续确认] ┐
│          ├─────────────────────────────────────────────────┤
│          │ 模型 / 图纸 / 并排工具        适配  投影  图层  │
│          │ ┌ 对象树 ┐                     ┌ 上下文侧面板 ┐ │
│          │ │ 输入   │                     │ 当前待确认   │ │
│          │ │ 工位   │  稳定的模型主视区   │ 来源与回答   │ │
│          │ │ 工序   │  初期可展开向导     │ 工序参数     │ │
│          │ └────────┘                     └──────────────┘ │
│          │              底部浮层安全区                     │
│          │       [公开状态 / 原生 composer / 审批]         │
└──────────┴─────────────────────────────────────────────────┘
```

左侧为约 220–260px 的对象树；右侧约 300–360px 的上下文面板，均可折叠。尺寸是初步设计参数，应按实际工作台宽度验收，不能按整个显示器宽度判断。当面板并列后画布不足时改用互斥抽屉。

输入文件显示已选择、待归档、已归档、已解析等明确状态，并显示对应指纹；工作目录路径收进详情。输入、执行、交付以侧边分组与对象列表呈现，避免为了看一个报告离开模型。

## 状态驱动的显示规则

| 状态 | 中央工作区 | 侧边与主操作 |
| --- | --- | --- |
| 尚未接件 | 两个 PRT/DWG 落点和任务目标输入 | 当前文件与格式问题；开始审图 |
| 分析中 | 图纸或已可用模型，显示真实分析状态 | 来源事实逐步出现；停止 Agent |
| 需要用户确认 | 首次展开聚焦的确认工作区，模型可作侧视 | 归并后的问题、依据与保存状态 |
| 必要确认已完成 | 收起确认区，回到当前正式 PRT 3D 主视区 | 要求摘要、下一阶段操作 |
| 几何未就绪 | 清楚的预览空态与生成/重试入口 | 区分连接问题、导出问题和用户确认 |
| 规划与授权 | 模型和关联工序，必要时展开工序表 | 当前工序属性及方案审核入口 |
| 执行与检查 | 模型或符合证据条件的刀路 | 真实任务时间线与检查缺口 |
| 问题包与修订 | 保留模型；按需打开文档 | 文件清单、版本、未决与反馈 |

首次自动展开只在当前任务的关键状态迁移发生，并且用户仍处于自动跟随模式时触发。用户主动打开图纸、文档或历史后，更新仅提示，不抢页。点击“完成确认”可以显式回到模型。相机、选择、当前文件与面板状态按会话保存；重启从正式输入恢复画布，不能再次显示泛化的“请先点文件”。

本次要求比目标文档更强调“单视图、按状态展开确认后回到模型”。实施前应同步目标文档 §3、§4、§6 与验收标准，消除其“稳定画布”与当前业务 TAB 实现之间的歧义。

## 实施顺序与验收条件

1. **先修可用性和范围。** 修 DWG 空白及尺寸溢出、深色空态按钮、底部安全区和回合状态命名；限制审图请求的目标范围；统一桌面控件样式。
2. **再改工作区组织。** 删除工作台业务 TAB，建立稳定画布、对象树和统一上下文面板；按正式任务状态展开确认；保存并恢复工作位置。
3. **最后完善动态确认。** 问题归并、来源展示、回答联动、系统任务重试和当前阶段缺项；同步 README、目标设计与手测文档。

验收必须使用指定两份文件在真实桌面重跑。至少覆盖最大化与较窄窗口、长公开回复、多附件及审批卡、面板同时展开、浅深主题和完整重启。判定条件：无主区域横向溢出；图纸有可见实体或明确失败状态；最后一个问题和画布工具可点击；同一字段不重复填写；引用只入草稿；未决仍阻止授权；任务范围保持审图；重启恢复正式文件及当前工作位置。

对应实现位置主要在 `ui-workbench/lib/client.js` 的 `WorkbenchView`、`TaskWizard`、`TaskAnswer`、`DwgPane` 和 `AgentPanel`；正式范围与状态仍由 `tool-cam` 维护。继续复用既有模型查看器和原生输入通道。

## 实施后的场景 1 回归

本节记录随后按用户确认方案完成的实现与回归，前文保留为改动前的问题记录。

工作台已改为模型画布和侧边对象入口，移除内部业务 TAB。审图确认由真实任务状态触发，在分析结束后临时展开；保存并稍后继续保留未决，完成确认后关闭向导及继续入口。该轮回归曾允许从加工要求查看和修改答案；此行为已由 2026-10-14 的只读确认清单替代。审图完成与编程授权分别核验，完成记录按输入、要求、问题和答案指纹保存。

使用指定两份文件新建“CAM脱料板镶件接件审图”会话，真实 Agent 归档并读取图纸。请求明确标记为场景 1 界面验收，并限定为图纸要求整理；回答保留顶针表差异和颜色公差核验边界，没有确认实际来料或装夹，没有建立工序。此回归验证的是界面完成路径，不证明零件要求已满足生产编程条件。

| 回归项 | 结果 |
| --- | --- |
| 真实接件与来源完整性 | 两个原件和正式快照 SHA 均匹配 |
| 当前请求范围 | goal 保持接件审图，没有扩大为 NC 交付 |

任务、预览、工作台、模型查看器和执行护栏自检通过。私有回归记录保存在 `.dsh/workbench-acceptance/scenario1-2026-10-13.json`。浅深主题、所有窄窗尺寸、图纸完整语义与后续编程流程仍需各自验收，不计入本次场景 1 的通过结论。

## 2026-10-14 交互与清单更新

当前已移除左侧零件/任务资料列，顶部合并文件标题，右侧以图标打开资料。紧凑输入完全浮在模型画布内，默认收窄、聚焦展开、多行自适应；响应只显示当前轮次最新工具活动或公开回复，不展示思考与等待套话。

确认向导改为居中限尺寸的逐题对话框，底部数字导航，选择建议或暂不确定后自动保存并前进。加工要求改为汇总勾选、整体核对后冻结，右侧只读展示同一清单。旧版完成记录没有清单快照时，顶栏提供临时确认入口，不能自动替用户确认。

本轮桌面核验了旧任务未确认空态、直接进入汇总、分组精简与整体核对前完成按钮禁用；没有替用户提交真实零件的最终清单确认。自检覆盖选中项冻结、重启持久化、变更失效与面板只读。该结果不扩展前文生产条件结论，也不表示所有主题和窄窗组合已测。
