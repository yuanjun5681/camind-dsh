# Camind 平台设计

> 状态：设计稿，2026-10-19。NX 工作台已有集群、队列与路由设计；本文其余平台能力为目标设计，不代表已实现或已通过生产验收。

## 1. 目标

Camind 为工厂提供从工艺规划、云端 NX 编程到设备执行的工作平台。现场工程师掌握方案、交付、加工执行和版本启用的批准权，设备 Agent 连接加工设备，Bot APP 提供远程操作入口。

研发端由 Agent 根据实际反馈自主编写代码、升级版本、完成测试并发布测试版。现场工程师审核测试结果并完成验收，批准后作为本站点正式版使用。

首期以一个工厂、一个控制中心和一台经过验证的机床完成全流程。

## 2. 系统组成

| 协作关系 | 交换内容与职责 |
| --- | --- |
| 桌面控制中心 ↔ Camind 服务 | 提交作业、反馈和授权证据，查询结果、工单与更新 |
| Camind 服务 ↔ NX 工作台集群 | 经集群统一入口提交和查询任务；集群内部通过队列与路由分配执行资源 |
| 现场顾问 ↔ 云端支持 Agent | 答疑、补充信息与问题跟踪；工单和证据授权由 Camind 服务保存 |
| 云端支持 Agent → 研发端进化 Agent | 转交明确的研发任务和获准使用的复现证据 |
| 进化 Agent → 受限发布流水线 → Camind 服务 | 自动检查、构建、签名和发布测试版及资源包 |
| 控制中心 ↔ 设备 Agent ↔ 加工设备 | 授权任务、程序传输、开工检查与执行结果 |
| 手机 / 平板 Bot APP ↔ 云端中继 ↔ 控制中心 | 用户对话、进度、审批与获准操作；现场主动建立连接 |
| 可选现场状态终端 ← 控制中心 | 最小必要状态、异常与待办；ESP32 是一种实现选项 |

### 桌面控制中心

现场工程师在桌面处理零件、确认加工要求、审核工艺、提交云端作业、检查结果和批准交付，也可查看设备检查结果并下达加工指令。控制中心还负责设备协作、资源包管理、版本更新和问题反馈。

每个站点由一个控制中心统一管理任务，桌面顾问 Agent 结合当前任务提供答疑、整理问题并确认反馈上传范围。审批、现场配置、交付物和使用记录保存在本地，并定期备份。现场服务与桌面窗口分离：关闭窗口不停止站点服务；退出服务、主机休眠或断网时，APP 显示不可用，恢复后先核对任务状态。控制中心更换或控制权移交时，须撤销旧端执行权限，避免两个中心同时下达设备指令。

### 云端

Camind 服务负责租户与站点、身份权限、业务作业、文件与证据、支持工单、版本资源、Bot 中继、用量及运维审计。它调用既有 NX 工作台集群，不重复建设集群内部的执行队列、节点路由或资源调度。

NX 工作台已有集群设计，通过队列和路由分配资源；各 NX 执行节点完成读件、几何处理、刀路生成和后处理，返回 NC、报告及执行结果。现场不部署 NX。集群承担执行资源管理、排队、节点选择和执行状态回报；Camind 承担客户归属、业务授权、输入版本、用户侧进度、交付及审计。已有集群设计不等于多租户隔离、配额或公平调度已经通过验证。

两端接口保留租户、站点、业务作业 ID、集群任务 ID 和输入指纹的关联。身份与归属由服务端校验，不直接信任客户端传入的租户标识。重复提交同一请求返回原任务；同一请求 ID 携带不同内容时拒绝，修改内容经重新确认后以新请求建立任务。断线后按原任务查询。取消须取得集群执行端的停止确认，执行结果绑定原任务和输入版本，结果文件按租户授权读取。隔离或取消结果不明的执行不得直接释放为可重新运行；先核对旧执行，防止并发副作用和迟到结果覆盖。

客户之间的执行环境、临时目录、文件和访问权限按已验证的边界隔离；共享节点复用须验证任务间清理。研发测试与生产执行环境分开。NX 许可容量、节点可用性和执行并发由集群管理，客户额度与限额由 Camind 管理并与集群准入衔接，不能维护两套互相矛盾的排队和执行状态。

### Camind 云端服务职责

下表是逻辑职责，可先在同一服务中实现，不要求拆成微服务。

| 模块 | 首期职责 |
| --- | --- |
| 租户与站点 | 建立企业、站点和资源归属；支持开通、停用、恢复、退出，以及数据导出、保留和删除 |
| 身份与权限 | 管理用户、角色、站点和设备范围；区分人员、Agent 与设备身份；注册、轮换和吊销凭据 |
| 站点与设备注册 | 绑定控制中心和设备，记录接口能力、在线状态、受测版本与控制权归属 |
| 业务作业与集群接入 | 校验授权与额度，关联业务作业和集群任务，查询进度、取消结果与产物；不重复实现 NX 调度 |
| 文件与证据 | 管理客户文件、内容指纹、访问授权、复现证据、保留期及备份恢复 |
| 支持与研发闭环 | 保存工单、补充信息、证据授权、研发任务、修复版本和现场验收结果 |
| 版本与资源分发 | 管理签名产物、兼容组合、站点启用记录、版本撤回与受影响任务查询 |
| Bot 中继与通知 | 校验用户和站点权限，中继到在线控制中心，提供进度与待办通知，不积压失效审批或启动指令 |
| 用量与额度 | 记录 NX、模型和存储用量，设置客户限额；首期不要求自动计费或复杂套餐 |
| 审计与运维 | 记录授权和关键操作、服务健康、失败告警、恢复过程及备份恢复验证 |

多租户边界贯穿数据库、对象存储、消息通道、作业队列、NX 执行目录、Agent 会话与记忆、检索结果、诊断日志和备份。不同客户的支持上下文分别保存；研发 Agent 仅取得当前工单获准使用的证据。不能以节点互信、文件前缀或登录成功代替租户隔离。首期即使只服务一个客户，也保留企业、站点和资源归属；接入第二个客户前完成跨租户拒绝测试。

租户停用时阻止新作业及新的远程操作，撤销相应访问；已在执行的加工按设备本地安全策略处理，不因账号或计费状态变化强行中断。退出时撤销连接和凭据，按约定导出、保留或删除数据。

### 云端支持与研发

云端支持 Agent 负责答疑、查询已知问题、分析经授权的证据、追问和跟踪工单。配置问题、操作疑问、设备故障与软件缺陷分别处理；需要修改软件、资源包或操作规程时，再把明确的验收要求和证据转交进化 Agent。两者是职责和权限边界，不要求部署成两个独立服务。

云端支持 Agent 不直接获得现场加工执行权、正式版本启用权或任意远程代码执行权。来自现场的文字、日志和附件作为不可信输入处理；Agent 的工具权限由服务校验，不能因对端已被信任而放开高权限操作。

### 设备 Agent

设备 Agent 运行在设备工控机或旁路边缘电脑上，接收控制中心授权的任务，完成程序传输、状态读取、开工检查和受控加工指令，并回报结果。设备接口操作由受限执行程序完成。

每台设备按已验证的接口和检查能力开放操作。具备远程启动条件的机床可由控制中心或 Bot APP 下令启动；检查证据不足的设备要求现场补充确认。急停与安全互锁始终由设备安全系统负责。

### Bot

手机、平板使用 Bot APP，可与控制中心 Agent 对话、查看进度、提交加工要求或方案草稿、处理审批，以及查看开工检查并下达获准的加工指令。Bot APP 是用户操作端；任务规划和工具执行由控制中心负责。

现场状态终端为可选组件，ESP32 是一种实现选项，不是独立 Agent 或首期必交硬件。优先显示 Camind 当前阻塞、待人工处理项、结果待审核和支援待办；已有机床 HMI、工业平板或信号灯能满足需求时，不新增硬件。首期终端只读，不承担审批、启动加工、急停、门锁互锁或开工许可。

每台终端只取得本站点最小必要状态，使用独立、可撤销凭据；断网或状态过期时显示“状态未知”，不继续显示为可靠正常。安装前验证油雾、粉尘、供电、无线覆盖、可见性和维护条件。呼叫支援按钮、语音咨询及辅助传感采集须另行确认需求和权限，不默认包含在只读终端中。

## 3. 公共资源包与数据存储

机床资料和通用工艺资产以公共资源包保存在云端数据存储中，供站点按权限下载和更新。

| 资源包 | 内容 |
| --- | --- |
| 机床包 | 机型、控制器、加工范围、接入说明及配套资产要求 |
| 刀具库 | 刀具规格、适用材料和建议加工参数 |
| 后处理器包 | 适用机床与控制器的后处理器及验证说明 |
| CAM 模板包 | 加工模板、工序模板和配套使用说明 |

资源包由研发 Agent 维护，自动完成检查和测试后发布待验收版本，说明适用范围、兼容版本、更新内容和授权条件。涉及第三方知识产权的资源按许可提供下载；公共资源不等于可以无条件公开分发。

站点选择适用资源包，下载后结合实际机床、刀具、夹具和现场参数完成配置与验证，再由工程师批准使用。更新先下载到待验收状态，不直接覆盖正在使用的资源；现场配置不会被公共包更新自动覆盖。

每次加工固定使用已批准的软件和资源包版本。资源包可以单独更新，但须与当前软件及相关资源兼容；正在执行的任务继续使用原版本。影响加工结果的更新需要重新验证后启用。

云端数据存储分别管理公共资源、软件版本和客户作业文件。客户图纸、PRT、NC、日志及企业工艺经验按客户权限保存，不随资源包发布。企业经验进入公共资源前，需要企业授权和审核。

## 4. 加工与交付流程

1. 用户通过桌面或 Bot 提交零件与加工要求，控制中心整理并请用户确认。
2. 控制中心经 Camind 服务调用 NX 工作台集群读件，形成工艺方案，核对机床、刀具和加工参数。高风险工序由工程师明确确认。
3. 工程师批准方案后，固定本次输入、方案、软件及资源包版本，经 Camind 服务提交集群任务，由 NX 工作台的队列与路由分配资源生成刀路和 NC。
4. 云端返回结果，控制中心校验文件完整性、工序与 NC 对应关系，并展示检查报告。计算完成与检查通过分别呈现，未解决的问题明确列出。
5. 工程师审核结果并批准交付；需要传到机床时，另行确认目标设备和程序。
6. 控制中心通过已验收的设备通信通道向设备 Agent 下发传输任务，ClawSynapse 为候选实现。设备 Agent 核对授权、文件和目标设备，完成传输并回报接收结果。
7. 设备 Agent 采集并核对开工条件，控制中心和 Bot APP 展示检查结果。获授权人员确认本次加工后下达启动指令，设备端即时复核并执行；缺少远程检查能力的项目由现场人员确认。加工后完成必要的首件验证。

控制中心保存方案、审批和交付记录；云端提供计算执行结果；设备 Agent 提供设备任务结果。仅到达边缘电脑的文件显示为“机床接收待确认”，取得机床接收凭据后才确认送达。

## 5. Agent 通信与远程操作

### 业务接口与 ClawSynapse 候选通道

首期现场反馈通过 Camind HTTPS API 提交工单、上传经授权的证据并查询进度，状态更新可先采用轮询。工程师身份、租户与站点权限、工单及附件授权由 Camind 服务校验和保存，不依赖 Agent 对话记录恢复业务。

ClawSynapse 是控制中心与设备 Agent、现场顾问与云端支持 Agent 之间的候选通信实现。固定版本并通过验证后，可承载节点认证、消息路由和文件传输；尚不将其视为已完成的多租户平台或安全控制层。设备注册、绑定站点并获得信任后才能接收任务；设备间的业务协作由控制中心协调。现场与云端通道优先采用主动出站连接，厂网可达性、认证和 TLS 配置须实际验证。

节点身份不等于工程师身份或业务授权。每项请求绑定持久业务 ID、请求指纹、租户、站点和目标设备，经权限检查后执行；同一业务 ID 且指纹一致的重复请求返回已有状态，指纹冲突则拒绝，不能仅按消息 ID 去重。通信 ACK 仅表示技术接纳，不等于工单受理、任务完成或机床接收。文件核对内容 SHA、接收路径、限额和目标归属，结果和异常按原业务 ID 回查。

候选通道须验证断网、重启、重复与过期请求、跨租户拒绝、凭据吊销、附件边界和持久化失效；不得静默降低已承诺的可靠性。不能确认持久投递时，依靠业务记录回查和幂等恢复；设备动作结果不明时禁止自动重发。通过前不开放生产设备执行。

桌面和 Bot 展示同一份 Agent 业务活动，包括任务请求、接受、进度、文件传输、完成和失败。活动按用户权限可见，展示公开对话和业务摘要，不暴露密钥、模型内部推理或客户文件正文。

### Bot APP 访问与审批

手机和平板 APP 通过云端中继访问现场控制中心；现场主动建立连接，工厂无需开放公网入站入口。可选现场状态终端通过本地受限只读入口获取状态，不直接连接云端 NX 集群或设备控制接口。

用户按角色和设备范围授权。远程提交的草稿、执行请求和审批使用与桌面相同的校验规则。审批需要确认用户身份、具体动作和批准内容，修改内容后重新审批；过期或重复提交的审批无效。

算刀路、交付、传程序和启动加工分别授权。软件与资源启用、现场参数修改由桌面端授权人员完成。控制中心离线时，Bot APP 显示不可用，不执行或积压审批与启动指令。

### 远程检查与加工指令

开工检查使用设备控制器、传感器和测量系统提供的实际证据。刀具身份及寿命、刀补、工件坐标系、目标程序、机床模式和报警等，在设备接口支持时自动核对；装夹可靠性需要夹紧检测、测量或现场确认，不能仅根据配置记录推断。

控制中心和 APP 显示各项检查的来源、时间及未确认项。工程师可远程复核并批准本次加工；必需条件无法确认时禁止启动，先补充检查或现场确认。装卸工件、换装夹具等实体操作仍需人员或具备相应能力的自动化设备完成。

设备 Agent 在执行前再次核对授权、当前程序和实时开工条件。方案、程序、装夹、刀具或坐标系发生变化后，受影响的检查和授权失效。远程启动仅对已完成安全验证的设备开放，网络指令不能绕过门锁、互锁和急停，也不能代替安全控制系统；APP 停止指令不作为急停保障。

## 6. 版本管理

软件版本覆盖控制中心、云端执行程序和设备 Agent 的受测组合。资源包单独管理版本，并明确与软件的兼容关系。加工记录保留实际使用的版本，便于检查问题和追溯结果。

版本分为三个阶段：

| 阶段 | 进入条件 | 使用范围 |
| --- | --- | --- |
| 候选版 | 研发 Agent 完成修改与初步验证 | 研发测试环境 |
| 测试版 | 自动检查与测试通过，Agent 完成构建和发布 | 现场维护期间验收 |
| 正式版 | 现场工程师验收并批准 | 本站点生产使用 |

管理员下载经过签名和完整性校验的版本，在维护期间安装。更新前停止接收新任务，确认已有任务结束，备份必要数据；各端版本匹配并通过现场测试后，工程师批准启用。测试期间暂停生产任务。

软件和资源包都由现场确认后更新。更新失败时保持维护状态，可恢复经过验证的兼容版本。涉及数据变更时，先确认备份、恢复和回退方案；回滚不能覆盖新产生的审批和任务记录。

版本被撤回时，通知受影响站点停止新任务并核查产物。回滚不会撤销已传到机床的程序或已发生的加工，现场需另行处理受影响程序和零件。

## 7. 版本自进化

### 现场反馈与云端受理

1. 工程师从加工任务发起反馈，现场顾问关联任务、软件及资源版本、问题现象、错误摘要与预期结果，先查询本地说明和已知问题。
2. 需要云端支持时，顾问列出拟上传的摘要与附件，脱敏后由工程师确认。正常云加工授权不自动包含研发复现；图纸、PRT、NC、日志逐项明确用途与范围，后续扩大范围须重新授权。
3. Camind 服务持久受理并返回工单 ID；提交超时后按原请求查询，不重复建单。本地未获受理时显示“待提交”，不能因消息送达便显示“已受理”。控制中心离线时可保存本地反馈草稿，恢复后仍须确认授权有效再提交。
4. 云端支持 Agent 分类处理、查询已知问题并请求补充信息；不需代码修改的问题通过答疑、配置指导或现场处理解决。需要研发时，建立关联研发任务，明确复现条件、验收要求和证据授权。
5. 进化 Agent 自主复现、修改并完成测试；通过受限发布流水线构建、签名并发布测试版，工单关联变更、验证报告和回退条件。
6. 现场工程师在维护期间验收并批准本站点启用。用户确认结果后关闭工单；验收失败或再次出现问题时重开，并保留原证据、处理记录和版本关联。

工单至少区分待受理、处理中、待补充、研发处理中、待现场验收和已关闭；记录每次流转的责任方及时间。反馈处理不因控制中心离线而丢失，设备审批和启动请求则继续遵循不离线积压的规则。

### 自主研发与现场验收

研发端仅由 Agent 完成复现、方案设计、代码编写、版本升级和测试，也负责资源包与操作规程改进。检查与测试未通过时继续修复或报告阻塞，不发布可供现场验收的测试版。

通过检查后，Agent 触发受限发布流水线，自动构建、签名并发布测试版，附带变更说明、测试结果、适用范围和回退条件。签名私钥和生产凭据由发布系统保管，进化 Agent 不持有，也不能修改发布规则。自动发布权限限于测试版，不能自行批准站点正式启用，也不能改变设备安全约束。

现场工程师审核测试版和验证报告，在维护期间完成现场验收；涉及工艺、后处理或开工检查的变更，须验证相应设备和加工结果。验收通过后批准本站点正式启用，无需研发端人工介入。一个站点的验收不自动授权其他站点启用，其他站点仍须按其设备、配置和兼容组合完成验收。

用户验收通过后关闭反馈，并关联修复版本。验收失败或使用中再次出现问题时，反馈重新进入 Agent 修复流程；必要时暂停使用并回退。资源包改进也遵循这一发布与现场验收流程。

## 8. 异常处理与数据保护

- 断网或重启后，已提交的云作业继续运行，恢复连接后核对原任务，不重复提交。设备和控制中心恢复后核对已有记录；无法确定结果时显示未决，确认停止或取得结果后再处理。
- 取消任务时，只有执行端确认停止后才显示已取消。云端执行异常时先隔离并核对原执行，防止旧结果覆盖后续结果。设备启动结果不明时禁止自动重发，先查询机床实际状态；已启动加工遇到通信中断时，由经验证的设备本地控制与安全策略处理。
- 离线时，可查看本地历史、准备方案、导出已缓存并校验过的 NC；生成新刀路和远程操作需要网络。
- 客户数据按权限保护，客户文件传输与存储加密，限定访问范围和保留期，审批与交付记录定期备份并验证恢复。用于研发复现的日志、图纸和 NC 经用户单独同意，不沿用正常计算的数据授权；授权撤销或到期后停止后续访问并按约定处理已有副本，已形成的版本与审批审计保留必要关联。
- 现场审批、配置和设备执行记录以现场为权威，云工单和云计算结果以云端为权威；跨端同步是带来源和版本的副本，不形成第二个审批写入口。现场恢复或更换控制中心时先恢复记录与权限，再开放执行；历史记录不能覆盖较新的任务或批准。

## 9. 使用场景

### 新零件编程与加工

工程师上传零件，说明材料、加工要求和目标机床。控制中心 Agent 经 Camind 服务调用 NX 工作台集群读件并起草工艺，工程师确认后由集群分配资源生成刀路和 NC。检查通过、交付获批后，设备 Agent 接收程序并完成开工检查。工程师在控制中心查看结果，批准本次加工；设备端复核条件后启动，并回传进度。

### 在 APP 查看和处理待开工任务

工程师不在机床旁，通过 APP 查看待开工任务和 Agent 活动。设备上报刀补、坐标系和程序已核对，但装夹尚未确认，APP 显示阻塞原因。现场人员完成装夹确认后，工程师可在 APP 批准启动；如果确认后又更换了刀具或工件，设备要求重新检查，不沿用原批准。

### 下载并启用机床资源包

工厂接入一台机床，工程师下载适用的公共机床包及配套后处理器、刀具库，结合现场设备完成配置和试件验证后启用。后续有资源更新时，先查看适用范围与变更，在维护期间验收；通过后用于新任务，正在执行的任务仍使用原版本。

### 使用反馈推动版本改进

用户发现加工报告缺少所需的刀具寿命信息，现场顾问关联当前任务并列出拟上传的诊断摘要，经用户确认后提交云端工单。云端支持 Agent 先确认设备是否提供寿命数据；若只是配置问题则指导处理，需要改报告时再转研发任务。进化 Agent 使用获准证据修改程序、补充测试并触发测试版发布。现场工程师在维护期间核对报告与实际数据，验收后批准本站点启用并关闭工单；未通过则反馈原因，重开处理。

### 可选机旁待办显示

现场已有机床运行灯，但操作员仍需反复查看电脑才能知道 Camind 是否需要人工处理。可试点一块只读状态屏，显示“结果待审核”“装夹待确认”等当前待办；断网或信息过期时显示“状态未知”。只有确认能减少查看和沟通成本、现有 HMI 或平板无法更经济地满足需求时，才部署 ESP32 等专用终端。

## 10. 交付验收

| 环节 | 验收结果 |
| --- | --- |
| 云加工与集群接入 | 真实零件经 NX 工作台统一入口完成读件、方案审批、刀路生成、NC 检查和首件验证；验证队列与路由分配、业务与集群任务关联、断线查询、幂等提交、取消确认和结果授权，不重复执行或混用产物 |
| 租户与站点 | 验证用户和设备绑定、凭据吊销、额度准入、跨租户拒绝，以及停用、恢复、退出和数据保留规则；隔离测试覆盖文件、任务、消息与 Agent 上下文 |
| 设备协作 | 候选通道固定版本并通过认证、TLS、可靠性、文件边界和租户隔离测试后，完成授权任务和文件传输，确认目标机床接收，并能查看设备状态与 Agent 活动；具备条件的设备完成开工检查、授权远程启动及执行回报，检查缺失或过期时拒绝启动 |
| Bot APP | 手机或平板 APP 完成对话、查看、草稿提交、审批和获准加工指令；越权、离线和无效请求被拒绝；关闭桌面窗口不影响现场服务，服务停止后明确不可用 |
| 资源包 | 完成下载、现场配置、验证启用及一次更新，原任务和现场配置不受影响 |
| 版本管理 | 完成测试版安装、现场批准、正式启用及兼容回滚，过程中保留任务与审批记录 |
| 支持与自进化 | 一条真实反馈经现场确认上传范围、云端持久受理和支持分析，转为研发任务；Agent 自主完成编码、升级、测试并经受限流水线发布测试版，现场工程师验收及本站点启用后关闭工单；补充授权、失败重开和跨站点不自动启用均可验证 |
| 故障恢复与运维 | 断网、重启、重复请求和取消不会造成重复执行或错误报成功，结果不明时停止重试并核查；备份可恢复，审计可关联人员、站点、任务与版本 |
| 可选现场状态终端 | 不作为首期必验项；决定部署时，另验状态来源与时效、断网未知显示、独立凭据和撤销、现场环境适配及只读边界 |

投入生产前，须确认 NX 托管及相关资产的商业许可、客户数据上传授权，以及目标机床的后处理、程序传输和远程控制验证结果。远程加工还需完成设备风险评估、现场互锁和检查能力验收。
