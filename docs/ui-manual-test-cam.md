# CAM 加工界面手测场景

通用 CAM 加工手测清单。可从新会话独立测试，也可按场景 1 → 2 → 3 在同一零件任务内连续测试；独立回归时须重新接件，不复用另一会话的确认或授权。流程以正式任务为准：接件 → 审图 → 确认向导 → 工序草案 → 工作台审核授权 → 执行 → 问题包交付 → 反馈修订。

## 测试材料

任选一个有 3D 模型和 2D 图纸的零件（本文以 zm26030-704 为例，换成自己的件时同步替换文件名与件号）：

```
/Volumes/UWorks/Projects/CAM/测试文件/zm26030-704/zm26030-704_stp.prt   # 3D 模型（.prt）
/Volumes/UWorks/Projects/CAM/测试文件/zm26030-704/ZM26030-704.dwg       # 2D 图纸（.dwg，正式输入之一）
```

机床用 `VMC-HJ-01`（华集 CV-850 立加，`.dsh/machines/` 里的种子档案）；换机床时先 `list_machines` 确认 id。

## 前置条件

1. 优先用 `sh ./scripts/desktop.sh` 启动真实桌面，确认使用本项目数据目录；浏览器辅助测试用 `node scripts/dsh.mjs web`，访问 `http://127.0.0.1:3080/`。桌面与浏览器共享工作台插件，但桌面使用官方壳。
2. Settings → Models 已配 `DEEPSEEK_API_KEY`。
3. 本机已装 GNU LibreDWG（`dwgread` / `dwg2SVG` 在 PATH）；缺装时 DWG 相关预期改为「如实报缺少本地 LibreDWG，不发送到第三方」。
4. 场景 2、3 需要 CAM-Agent proxy 可达：Settings → 插件 → 插件配置 →「NX 工作台」填 baseURL 与 token，「测试连接」返回 base_dir / proxy_version；NX 队列空闲、无未保存模型。场景 1 不需要。
5. 新会话选择 **CAM 加工** preset；加工会话默认落在「工作台」标签。
6. 上传方式：web 与桌面都在 composer 上传（桌面文件选择器可能插入本地路径引用；正式归档状态以任务快照为准）。桌面 composer 里 `@` 绝对路径只是**路径引用**不是上传：可分析，但正式接件仍以向导归档验证为准。

## 场景 1：接件、图纸与确认向导

验证双文件归档、DWG 本地解析、来源区分与向导答题。不需要 NX。

**操作**：新会话 → 上传 3D 模型和 2D 图纸 → 发送（件号换成自己的）：

```
我上传了 zm26030-704 的 3D 模型和 2D 图纸（zm26030-704_stp.prt / ZM26030-704.dwg）。
请先接件审图：归档两个输入、读取图纸标注、整理材料与技术要求，缺什么列给我。
```

**交互过程与预期**：

1. 模型用 cam_task 归档两个文件（也可在 Agent 接件过程中归档会话文件）；原件不覆盖，输入显示文件名 + SHA 前缀。
2. 顶部「CAD 图纸」入口显示本地转换预览（页面上方有「部分二维实体预览，须核对原图」说明）；右侧标注列表可点选，「添加标注到提问」把标注作为引用 chip 插入输入框草稿——只入草稿，不发送、不执行。
3. 模型用 read_drawing 读标注原文；图纸数值必须标注为「图纸属性，不是 NX 实测」；未读取、未知实体、颜色公差保留为未决项。
4. 分析结束后临时展开审图确认：核对 PRT/DWG 对应范围及当前审图冲突；不重复填写图纸已读信息，毛坯/基准/装夹留到规划。向导每次只显示一题，顶部显示题号/处理进度/已确认数，底部步骤导航可跳转回看；「使用建议」自动保存建议原文并进入下一题，「暂不确定」保存未决后前进，「其他建议或补充」填写并保存后前进。保存失败不跳步；来回切题不丢失本次补充草稿。最后在汇总核对按类别整理的加工要求，取消不应纳入的条目，勾选整体核对后点「完成确认」：向导与「继续处理」消失，主区回到正式模型，顶栏显示审图完成；「暂不确定」保留未决并允许稍后继续，不能完成。「加工要求」只读显示汇总页最终确认的条目，不显示问答和修改入口。
5. 工作台顶栏显示 `R1` 与阶段（如「审图待确认」「审图完成」），阶段来自正式任务状态，不是模型自述。
6. 顶部「3D 模型」入口的 PRT 三维渲染**需要 proxy**：首次点「确认并生成三维预览」经 NX 五步导出几何包（独立副本、不覆盖源件），之后走缓存不再访问 NX。本场景不验收三维渲染；无 proxy 时预览区停在「尚未生成三维预览」属正常。

**通过要点**：

- 缺双文件或当前审图问题未解决时，「完成确认」不可用；「暂不确定」正确保存。审图完成后，缺编程前置条件仍不能「审核并确认方案」。
- 真实重启后保持审图确认完成，恢复正式模型入口；不能重新出现常驻向导或已完成的待确认项。
- 上传原件留在 `$DSH_HOME/uploads/<session>/<batch>/`；正式快照是 `$DSH_HOME/cam-tasks/<session>/` 下的只读副本，会话工作区根目录干净。

## 场景 1 补充回归：布局、输入与确认清单

1. 顶部仅一行文件标题，旁边为新窗口打开、3D/CAD 入口和修订状态；没有左侧“当前零件/任务资料”列。右侧五个图标可显示名称提示、切换对应资料并收起，画布获得释放的空间。
2. composer 完全浮在模型画布上：空草稿默认约 360px，一行输入与提交图标；点击后展开（最多 760px），有草稿保持展开，清空并离开后收窄。换行和自动折行自适应高度，达到上限后内部滚动；打开右面板后仍相对实际模型视区居中。
3. 提交后只显示当前轮次最新工具活动或公开回复的一行状态，无思考内容、无“正在回复/等待公开输出”套话；无关键信息时隐藏该行，结束恢复输入。切到官方对话可看到同一次请求，草稿、附件和引用不复制、不丢失。
4. 向导居中且尺寸受模型视区限制，正文滚动、操作固定；进度条下无额外分割线；补充输入聚焦时左右边框完整。数字步骤导航位于底部上一题和下一题之间。
5. 汇总的选中清单与完成后右侧逐项一致，材料/公差数值和单位不丢；没有身份字段重复、任务目标、问答、原文证据、内部实体信息或编辑入口。未采纳建议不出现，已采纳的待提供资料只列为补充约定。
6. “暂不确定”、无选中要求、未勾整体核对、输入指纹变化或保存冲突均不能伪装成完成；失败不跳题、不丢补充草稿、不重复提交。
7. 确认后完整重启，清单和模型恢复，向导及继续入口不常驻。旧版完成任务若无清单快照，右侧显示尚未确认，顶部“确认加工要求”直接进入汇总；不得替用户自动完成整体确认。
8. 在独立测试任务中更换输入或修改要求/回答，旧清单应隐藏并提示重新确认，旧签字不得自动继承。此操作不在真实生产任务上试做。

以上回归至少覆盖右面板开合、较窄窗口、长问题、长补充文字与重启。尚未实测的主题/窗口组合记录为未测；只读清单确认不代表生产编程授权。

## 场景 2：读件与特征确认

验证 3D 读件、事实绑定版本与高风险候选提示。需要 proxy。

**操作**：接场景 1 同会话（或新会话重新完成接件）→ 发送：

```
读取正式 PRT 的几何事实：有哪些特征、有没有疑似攻丝或沉窝的地方？
```

**预期**：

- cam_survey 读取 `task-input://<修订>/prt`（内容寻址上传远端）；零件事实绑定源件 SHA 存入正式任务，任务里能看到 NX 事实来源。
- 攻丝/沉窝以「候选供人确认，非判定」措辞出现。
- NX 队列忙或有未保存模型时如实拒绝并说明，不切换、不关闭他人模型。

## 场景 3：授权执行与问题包交付（核心场景）

验证从方案审核授权到执行、问题包交付与放行拒绝的完整链路。两种方式二选一：A 贴近真实使用（自然描述 + 交互纠偏），B 固化约束直跑（回归验证用）。

### 方式 A：自然描述 + 交互反馈

**操作**：完成场景 1/2 后同会话发送（声明换成自己的）：

```
继续这个任务：为 zm26030-704 生成刀路并交付 NC 工艺包。材料 AL6061，无热处理，
半成品来料；目标机床 VMC-HJ-01，本次只做一道粗铣，无攻丝/沉窝/螺纹。
工序草案整理到正式任务后告诉我，我去工序表审核。
```

**交互过程与预期**：

1. 模型补齐事实并起草工序（来源分为：NX 实测 / 图纸原文 / 用户确认 / Agent 建议）；缺口在确认向导问你，回答后草案更新，不要求重填。
2. 打开侧边「工序方案」：核对一道 from_scratch 粗铣工序。可直接编辑名称/工位/刀具引用/转速/进给/依赖/检验项或重排——保存会撤销旧授权并按用户操作审计；后台已变更时提示冲突不覆盖。
3. 点「**审核并确认方案**」：核对冻结指纹、输入/机床/后处理/工序快照；「允许自动调整的范围」默认全不勾（只允许 from_scratch 工序的转速/进给区间）；勾选「我已核对当前冻结版本和上述范围」→「确认方案」。
4. 告诉模型「方案已确认，执行吧」→ cam_plan 绑定冻结批次 → cam_run 直接开始。**正式批次不再弹执行签字卡**（冻结授权即批准）；底部 Agent 面板显示真实执行状态与最新公开输出。
5. 结束后右侧「加工记录」时间线列出逐工序终态与 NC 对账；检查覆盖不足如实写明，overall 显示 incomplete。
6. 回复「交付」→ 弹出确认卡「**问题包打包确认（不是生产放行）**」→ 批准 → 右侧「交付文件」出现交付三件套与 nc/ 文件；报告首部标明「问题包：禁止作为已放行生产程序」并列出全部缺口。
7. 检视面板对该批次点「**核验放行条件**」→ 必须拒绝并列出缺失证据（完整夹具/真实刀柄/残料/工位回读/后处理资格等）；人工签字不替代证据。
8. 「加工记录」中的「查看刀路」：切削蓝线、快移红线、可关图层；点刀路或点源码行双向跳转。刀路是近似轨迹展示，不是碰撞仿真或生产验证。

### 方式 B：固化约束直跑

**操作**：新会话上传两个文件、完成场景 1 接件与向导后发送（**只需替换文件名与件号**；工序约束已固化、不要删改——铣削参数按你的机床档案切削参数表调整）：

```
按下面的约束把工序草案存进正式任务（不要自由发挥工序类型），存好后停下等我审核：
- 一道 from_scratch_workpiece_op：id=OP10，station=A，new_name=ROUGH_{suffix}，
  depends_on=[]，execution=nc，inspection=["NC对账","装夹未核验，仅问题包"]，
  geometry=FS_WORKPIECE，parent=MCS_MAIN，subtype=CAVITY_MILL，
  tool=AP_MILL_D10（init_setup 会造这把刀），tool_assembly_id=END_MILL_D10_ROUGH，
  spindle=8000，feed=2400
- prepare.init_setup=true，post_name=三菱备刀，machine_id=VMC-HJ-01
```

之后与方式 A 第 2–8 步相同。

**常见翻车点（均属能力边界，不是新 bug）**：

- 模型若把工序起成钻孔类 → 没有从零建钻孔序的能力，必败；只让它排铣削工序。
- post_name 必须用 worker 上**已注册**的后处理器名（华集机目前是「三菱备刀」）；机床档案里 DRAFT 状态的后处理（如「三菱M80_华集CV850」）未注册，用了报「CLSF 格式或后处理机床类型未找到」。档案展示名不等于注册名。
- 模板复制（copy_postprocess）不应用显式转速/进给，cam_plan 会拒绝带这些参数的模板工序。
- 含外协（execution=external）工序的路线暂不能进入自动 NC 批次（已知边界）。
- 工序失败时错误消息应带 worker 真因（如 missing groups: ['D10'] = 漏 tool 字段），按提示修正后重新审核授权再跑。
- 任务显示「执行状态未知」时，先核实远端 NX 队列与工作副本；当前没有界面自助恢复入口（已知缺口），不要改对话里重新催跑。

## 场景 4：同任务反馈修订（R2）

验证交付后原任务内修订、旧包保留。

**操作**：场景 3 交付后同会话，在右侧检视面板「反馈及实测证据」填写具体证据（如「现场实测孔位偏小 0.05，量具编号 XX，使用 R1 批次 NC」）→ 点「建立同任务修订」→ 确认。

**预期**：

- 任务变 `R2`：授权撤销、工序与装夹确认清空、要求标「待重新核对」；旧输入与 R1 交付包保留。
- 磁盘核对：`$DSH_HOME/cam-runs/<session>/<runId>/delivery/` 内容 SHA 不变；该批次再次交付被闸绝（不可覆盖），只能走新批次。
- 模型读取当前任务，按反馈影响重建草案，重新走确认 → 授权 → 执行 → 打包；反馈本身不提交 NX。

## 场景 5：经验沉淀到记忆库

验证交付后的经验提炼与人工审核流转。

**操作**：场景 3/4 完成后，同一会话发送：

```
把这次加工的关键经验沉淀到记忆库。
```

**预期**：

- 模型提炼候选经验；侧栏「记忆库」→ 经验 tab 出现该候选（元数据「生成中」→ 自动补全）。
- 人工在页面审核：采纳 / 弃用 / 编辑退回候选。经验只能预填参考，不替代下一件的确认。

## 通过标准

- 方案授权只能在**工作台 UI** 完成（审核页勾选 + 确认按钮）；聊天里说「确认」不改变授权状态。
- 正式批次 cam_run 不弹签字卡；cam_deliver 弹一张「问题包打包确认」卡，批准前无实际远程动作。
- 交付产物一律是**问题包**（manifest 带缺口清单与 NC 回读），原子冻结不可覆盖；放行核验必拒绝并列出缺失证据。
- 底部「停止」只停 Agent 当前生成，不承诺 NX 已停止；NX 任务状态以「加工」时间线与远端核实为准。
- 修订不覆盖旧输入、旧方案与旧包；新修订必须重新审核授权。
- 失败路径全部给中文可操作错误，不静默、不编造。
- 磁盘核对：`$DSH_HOME/cam-tasks/<session>/task.json` 有版本、来源与审计；`$DSH_HOME/cam-runs/<session>/<runId>/delivery/` 含三件套 + manifest.json，nc_batch.zip 开包是 .nc（含 G1/G2/G3 真实刀路）。
