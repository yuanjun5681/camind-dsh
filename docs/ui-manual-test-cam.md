# CAM 加工界面手测场景

通用 CAM 加工手测清单。每个场景都是**独立完整任务**：新开一个会话、重新上传文件，场景之间互不依赖。

## 测试材料

任选一个有 3D 模型的零件（本文以 zm26030-704 为例，换成自己的件时同步替换文件名与件号）：

```
/Volumes/UWorks/Projects/CAM/测试文件/zm26030-704/zm26030-704_stp.prt   # 3D 模型（.prt）
/Volumes/UWorks/Projects/CAM/测试文件/zm26030-704/ZM26030-704.dwg       # 2D 图纸（.dwg，用于边界验证）
```

机床用 `VMC-HJ-01`（华集 CV-850 立加，`.dsh/machines/` 里的种子档案）；换机床时先 `list_machines` 确认 id。

## 前置条件

1. `node scripts/dsh.mjs web` 已启动，浏览器开 `http://127.0.0.1:3080/`。
2. Settings → Models 已配 `DEEPSEEK_API_KEY`。
3. 场景 2 需要 CAM-Agent proxy 可达：Settings → 插件 → 插件配置 →「NX 工作台」填 baseURL 与 token，「测试连接」返回 base_dir / proxy_version。场景 1 不需要。
4. 新会话选择 **CAM 加工** preset。

---

## 场景 1：读件与特征确认

验证 3D 读件、高风险候选提示、2D 图纸能力边界。

**操作**：新会话 → 上传 3D 模型和 2D 图纸 → 发送（件号换成自己的）：

```
我上传了 zm26030-704 的 3D 模型和 2D 图纸。帮我读取这个零件的几何信息：
有哪些特征、有没有疑似攻丝或沉窝的地方？图纸里的材料和技术要求也读出来。
```

**预期**：

- 3D 读取成功：零件事实（尺寸/特征/孔清单），攻丝/沉窝以「候选供人确认，非判定」措辞出现。
- 2D 图纸**解析不了会如实说**（v1 不支持 .dwg），不编造图纸内容；材料/螺纹/公差等转而请你口头声明。
- 上传文件只进 `$DSH_HOME/uploads/<session>/<batch>/`，会话工作区根目录干净。

## 场景 2：生成刀路端到端（核心场景）

验证从读件到刀路生成、NC 产出、交付与刀路回放的完整链路。两种方式二选一：A 贴近真实使用（自然描述 + 交互纠偏），B 固化约束直跑（回归验证用）。

### 方式 A：自然描述 + 交互反馈

**操作**：新会话 → 上传 3D 模型 → 发送（件号换成自己的）：

```
我上传了 zm26030-704 的 3D 模型（zm26030-704_stp.prt），材料 AL6061，无热处理，
半成品来料。为这个零件生成刀路并交付 NC：目标机床 VMC-HJ-01，本次只做一道
粗铣，无攻丝/沉窝/螺纹。
```

**交互过程与预期**（模型每步都会停下来等你反馈）：

1. 读件后模型可能反问工艺事实（来料状态/高风险项）——按你上面的声明回答即可。
2. 模型起草工序单请你**过目**：核对一道 from_scratch 粗铣工序（铣削参数、init_setup、后处理「三菱备刀」）。若工序单明显不对（如排了钻孔、漏了 tool 字段、post 名错），直接用日常语言指出，让它修正后重新落盘。
3. 你回「确认，落盘/执行吧」→ **签字卡**弹出，点批准 → 后台执行，阶段卡推进，结束出检查报告卡。
4. 若某工序失败：错误消息会带 worker 真因（如 missing groups: ['D10'] = 漏 tool 字段），把它的话转述成指令让它修正重跑（或 resume 续跑）。
5. overall=ok 后回「交付」→ 第二张签字卡 → 交付卡上点「**查看刀路**」。

这条路径同时验证了模型的交互引导能力：声明问齐、工序单过目、签字两卡、失败如实转述不编造。

### 方式 B：固化约束直跑

**操作**（方式 B）：新会话 → 上传 3D 模型 → 发送（**只需替换文件名与件号**；工序约束已固化、不要删改——铣削参数按你的机床档案切削参数表调整 spindle/feed/tool_assembly_id）：

```
我上传了 zm26030-704 的 3D 模型（zm26030-704_stp.prt）。
目标：为这个零件生成刀路并交付 NC。

请先读件，然后按下面的约束规划（不要自由发挥工序类型）：
- 工艺事实以我声明为准：材料 AL6061，无热处理，半成品来料；本次只做一道粗铣，
  无攻丝/沉窝/螺纹，无需高风险声明。
- 裸件，工序单用一道 from_scratch_workpiece_op：
  geometry=FS_WORKPIECE，parent=MCS_MAIN，subtype=CAVITY_MILL，
  tool=AP_MILL_D10（init_setup 会造这把刀），tool_assembly_id=END_MILL_D10_ROUGH，
  spindle=8000，feed=2400
- prepare.init_setup=true，post_name=三菱备刀，machine_id=VMC-HJ-01
工序单给我过目后落盘，我确认后你执行，完成后交付。
```

**过程与预期**：

1. cam_survey 读件 → cam_plan 落盘，返回 run_id。
2. 回复「确认，执行吧」→ 弹出**签字卡**（件号/机床/工序数/高风险项），点批准。
3. 后台执行（NX 独占，数分钟）：阶段卡（cam/stage）逐步推进，结束出**检查报告卡**，overall 应为 **ok**。
4. 回复「交付」→ 第二张签字卡 → 批准后出**交付卡**：NC 清单 + 三个下载链接。
5. 交付卡点「**查看刀路**」：WebGL 回放（拖动旋转、滚轮缩放），切削蓝线、快移红线。
6. 「交付物」页签有三件交付文件；「加工」页签列出该 run。
7. 磁盘核对：`$DSH_HOME/cam-runs/<session>/<runId>/delivery/` 三件套齐全，nc_batch.zip 开包是 .nc（含 G1/G2/G3 真实刀路）。

**常见翻车点（均属能力边界，不是新 bug）**：

- 模型若把工序起成钻孔类 → v1 没有从零建钻孔序的能力，必败；只让它排铣削工序。
- post_name 必须用 worker 上**已注册**的后处理器名（华集机目前是「三菱备刀」）；机床档案里 DRAFT 状态的后处理（如「三菱M80_华集CV850」）未注册，用了报「CLSF 格式或后处理机床类型未找到」。
- 工序失败时错误消息应带 worker 真因（如 missing groups: ['D10'] = 漏了 tool 字段），按提示修正后重新落盘即可。

## 场景 3：经验沉淀到记忆库

验证交付后的经验提炼与人工审核流转。

**操作**：场景 2 交付完成后，同一会话发送：

```
把这次加工的关键经验沉淀到记忆库。
```

**预期**：

- 模型提炼候选经验；侧栏「记忆库」→ 经验 tab 出现该候选（元数据「生成中」→ 自动补全）。
- 人工在页面审核：采纳 / 弃用 / 编辑退回候选。

---

## 通过标准

- 两张签字卡（cam_run / cam_deliver）都必须出现，批准前无实际远程动作。
- 失败路径全部给中文可操作错误，不静默、不编造。
- 已知上游缺陷不算失败：含 cam/* 事件的会话日志进程重启后拒绝重载，历史以 run 目录落档为准。
