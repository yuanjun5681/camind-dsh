# dsh 升级记录：0.1.1-rc.2 → 0.2.0-rc.2

日期：2026-10-10。上游 tag `dsh-v0.2.0-rc.2`，commit `639ed015397290b3745d163aafe02ffee4aa3f84`。
跨域大版本（中间隔 0.1.2~0.1.7 全部迭代），客户端架构与宿主服务面都有重构。

## 上游 breaking changes（本次实际踩到的）

1. **客户端布局重构**：`conversation` 单坑改为 keyed `main`（会话占 key `conversation`，插件管理/自动化任务各占 key）；`details` 删除，右侧栏归 ui-sidebar-right 占 `rightbar`；新增 `sidebar.panellist`（全局面板行）、`sidebar.toggle.badge`、`shell.leading`（窗口镀铬席）。`root` 变为运行时内建席（注册进去就是顶替官方 AppFrame，文档明示动态注册低优先级获胜）。
2. **客户端服务面收敛**：`ctx.sessions` 仍是 ISessions 但删掉 `open/clear` 与 `list.current`（当前会话 = 列表行 `retainedBy.mainView > 0`）；`ctx.workspaces` 删除，导航归 `ctx.uiWorkspace`（openSession/openWorkspace/startSession）；新增 `uiSession`/`uiConversation`（投影绑定 `uiConversation.binding(sessionId).snapshot`）、`shortcuts`、`productAnalytics`、`configForms`、`remote.*`（remote.credentials 等）；`ctx.layout` 契约改为 `panelInfo/selectPanel/beginNavigation/toggleSidebar/openRightbar/closeRightbar`，`usePanelInfo` 由布局方 `slots.provideRoot({hooks:{panelInfo}})` 供出。
3. **Composer/附件**：`InputState.imageIds` → `attachmentIds`；`conversation.input.left` 不再有 owner props（只剩标准 session props）；`conversation.input.dock` owner 缩为 `{ session, input }`（inputActions 删除，动作走会话输入机 `conversation.input.for(actx)`：`state`/`setDraft`/`addAttachments`）；草稿附件 API 为根服务 `ctx.conversation.createDrafts/releaseDraftAttachments/resolveDraftAttachments`（图片/文件自动分流）。
4. **引导协议**：图行 URL 全部改文档相对（`plugins/??…`，为反代子路径去斜杠），`__DSH_BOOT__` 强制携带 `batches`（combo 脚本，每 entry 恰属一批）；模块系统 `create()` 后把 facade.load 改写为 live 注册，combo 批次会注册批次内全部 factory——本地预注册顶替（layout/sidebar）必须在 live 口子上吞掉同名官方注册，否则 duplicate factory throw 中断批次余量。
5. **浏览器门禁**（0.1.7 引入）：`GET /?token=<launchToken>` 铸签名 cookie + 303，仅 `pathname === '/'` 触发；官方 index 与 `/api/*`/WS 全走 `connection` 鉴权。自定义 `/` 302 必须先委托 `ctx.connection.authorizeIndex(req,res)`，自定义 API 用 `connection.requestRejection({headers})`（401|403|undefined）同口径拦截。
6. **Settings 即插件条目 config**：`installSettingsSection`/`settingsNamespace` 从 `@deepseek-ai/dsh-settings` 删除；`SettingsForms` 按 cordis 条目 id 服务表单（schema 取插件模块导出的 `Config`，只收 `.volatile()` 字段），值写 profile patch 的条目 config；volatile-only 编辑原地热更（cosmokit cell + `loader/volatile-update`），非 volatile 变更重建 fiber。旧 `$DSH_HOME/settings.yaml` 首启自动迁入活动 profile（`settings.yaml.imported`），仅识别「节名 == 条目 id」。
7. **会话持久化**：格式升到 V4（V0~V3 静态迁移链自动迁移，实测 0.1.1 的 v0 日志正常列出）；`sessionPersistence.inspect` 删除（冷读 = `open(id,'read')` 句柄 + `read()` + `close()`），`list()` 返回轻量快照 `{header, revision}`；宿主 `Session.events` 同步属性删除，快照读走 `snapshotEvents()`（deprecated 但可用）。
8. **会话卡片席位**：`settings.plugin.item`（keyed by namespace）删除，插件配置进官方「插件」页：`plugins.item`（list，summary/page 双视图）/ `plugins.bundle.config`（keyed by 包名，bundle 详情页）/ `plugins.row.config`（keyed by `包名#行id`）。
9. **ui-primitives 图标改名**：`Icon<Name>Outline16`/`Fill14` 等带尺寸后缀全部改为 `Icon<Name>OutlineRegular/Medium`（尺寸走 `size` prop）；`ConnectionBanner`/`OnboardingSurface`/`MessageText` 删除，`invariant.ts` 从各包删除。静态表新增 `@deepseek-ai/dsh-client-store` 与 `@deepseek-ai/dsh-client-ui-dockkit`（`dsh-client-runtime` 包不在了，`createSnapshotStore` 改从 store 包）。ui-primitives npm 包不再传递任何运行时依赖（全在 devDependencies），vendor 源码消费需自钉 `diff@^9`、`simple-icons@16.31.0`、`zustand@~4.4.7`、`immer@^10` 及三个 `@deepseek-ai/dsh-*` 0.2.0 包。
10. **`@deepseek-ai/dsh-persona` 配置拆分**：`text` → `prefix`(+`suffix`)（0.1.3 起）。
11. **会话内 turnTail**：`conversation.chat.turnTail` 从 chain 变 list（0.1.7 已变），`select` 不再生效——链式「接管」玩法失效，entry 自行读 owner 数据、无内容返回 null。

## 升级后修正（2026-10-10 复审发现）

- **自写「+ 文件」按钮删除**：0.2.0 官方 composer 的 + 菜单自带「文件」上传（+ 反馈/指令项），`conversation.input.left` 的自定义上传入口移除（ui-shell officialClient.ts + WorkspaceFileUpload.tsx）；Camind 会话隔离上传批次仍由 dock 的拖放分流 + pending rail 承担（该路径进 `$DSH_HOME/uploads` 供 cam_* 工具读取，与官方附件体系并存）。
- **NX 工作台独立配置入口**：0.2.0 设置面板仍有 `settings.section` 席位（每 entry 一页，账户/通用/模型/内置插件同席）——配置卡除官方插件页详情外，注册设置面板「NX 工作台」节（id `cam-nx`，order 30）。入口即设置面板左侧导航；曾加过侧栏底部菜单直达项（经 slots 内部 storeOf 调 `openSection`），后按用户要求撤掉。
- **cam-machining preset 回归**：0.2.0 删除 `.agent-presets/` 目录发现器（无任何代码再读该目录），preset 变为 `@deepseek-ai/dsh-agent-preset` 声明行（web-app bundle 的 `presets/<id>.patch.yml` 即此形态，`dsh.bundle.patch` 支持文件列表）。迁移：`agent-presets/cam-machining/` 改为 patch-only bundle `camind-preset-cam-machining`（preset.yml 展示元数据 + agent.cordis.yml 条目合并进 cordis.patch.yml 单文件，旧两文件删除）；init.mjs 去掉 .agent-presets 同步、web profile 模板与该 profile 实装各加 bundle；`.dsh/.agent-presets/` 清空。registry 只在 web-app bundle——preset 仅 web profile 挂载（与 0.1.1 行为一致：headless 不选模式）。验证：presets API 列出 cam-machining（无 broken），模式菜单第二位可选中，选中后 composer chip 显示「CAM 加工」。

## 遗留事项

- 自写 Electron 壳 `desktop/` 已于同日删除（0.2.0 起上游官方提供桌面应用，与 CLI 共享 `$DSH_HOME`）；本仓库不再产出安装包。官方桌面端的 Camind 接入：`scripts/desktop.sh`（`DSH_HOME`=项目 .dsh 直接 exec App 内二进制）+ init.mjs 新增 desktop profile 模板（bundle 与 web 一致，另手工补了 tool-cam 条目 config）；实测桌面窗口加载 camind 插件图与 CAM 加工模式（记忆库菜单、CAM 加工 chip、宿主侧 presets/memory API 全部正常）。桌面窗口渲染官方烘焙前端（`dsh-app://` 不经 Host 路由），/camind 定制 SPA 在桌面端不可达；该应用窗口不注册 AX 树，GUI 自动化只能截图。
- 官方 HeroShell 隐藏的新锚点（`… > div > div:first-child`）仍是结构选择器，升级需复核（SOP 已列）。
- ui-preview 切页内部面（hostFace().storeOf）本次已按 0.2.0 修复可用，但仍是非公开 API，升级继续复核。
- 会话「选中清除」无公开 API（clearMain 是 ui-workspace 私有）：插件页内会话行保持高亮，与官方全局面板行为一致，不再强行清选。
- `Session.snapshotEvents()` 上游标 deprecated（新代码禁用）；本桥沿用旧读面，后续宜迁 async 读或投影。
- 本机 Node/Python 直连 LAN 的 EHOSTUNREACH 老问题依旧（curl 可达）；cam ping 在本机因此报无法连接，非本次升级引入。
- `docs/slots.md` 表体仍是 0.1.x 快照，未逐行重写。
