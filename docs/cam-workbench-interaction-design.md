# Camind 加工工作台交互设计

> 状态：经用户确认的目标方案，2026-10-12。本文不表示所述能力已经实现。
> 范围：接件、审图、规划、编程、校验，直到交付 NC 工艺包；现场反馈可以开启修订，再次交付。不包含现场生产管理、终检管理或多角色协作。
> 流程依据：[CAM 加工最小工作流程建议](cam-machining-minimal-workflow.md)。

## 1. 产品定位与已确认决策

Camind 是普通使用者通过 Agent 完成加工编程交付的工作台。用户可能具备部分工艺、编程能力，但不要求独自完成全部专业判断。Agent 主动整理证据、推荐方案、编排任务和执行，用户主要审核、确认，并补充机器无法获得的信息。

主界面围绕零件和加工结果展开，不再以聊天记录为正文。

| 决策 | 方案 |
| --- | --- |
| 使用者 | 一个普通使用者；不引入工艺主管、编程员等角色体系、代签或权限流转 |
| 软件终点 | 已放行的 NC 工艺包；不以此证明实物零件合格 |
| 默认入口 | 加工任务默认进入“工作台”，排在“对话”“轨迹”之前 |
| Agent 自主权 | 主动分析、生成建议与正式草案；在明确授权范围内连续编程、检查、修复 |
| 人工主要确认 | 方案授权执行、工艺包放行交付；关键变更另行确认 |
| 输入文件 | PRT 和 DWG 均须上传；可先提供一个开展部分分析，但不能据此放行方案或编程 |
| 提问方式 | 动态确认向导，依据已获得信息生成，不让用户重复填写 |
| 工作流 | skill 定义方法与必要检查，Agent 按 prompt 生成具体行动计划 |
| 现场反馈 | 原任务内开启修订轮次，保留历史交付物，不覆盖旧包 |
| 首期布局 | 中央画布、可折叠检视面板、底部 Agent 面板；不做自由拖拽窗口编辑器 |

专业能力不足不能通过少点几个按钮解决。无法证明设备能力、要求不完整、工具不支持时，应明确停在对应问题上，不让用户通过笼统“确认”替代缺失证据。

## 2. 信息架构

### 2.1 会话级标签

```text
工作台（默认）  |  对话  |  轨迹
```

- **工作台**：当前任务的输入、模型、图纸、要求、工序、检查、交付与修订；底部可与同一个 Agent 交互。
- **对话**：完整消息和历史问答，复用官方会话，不新建另一条聊天记录。
- **轨迹**：工具执行、详细错误和调试证据，不承担正式工艺记录。

文档、模型、图纸和刀路的常用入口在工作台内打开，不必在多个预览标签间跳转。通用“预览”可保留给非加工附件或兼容入口，但不再是加工工作主入口。

加工任务首次进入时默认工作台；用户主动切到对话或轨迹后，不因新消息、进度更新或轮询强制切回。再次打开任务恢复上次选择；没有有效偏好时落在工作台。纯咨询会话不强制变成加工任务。

### 2.2 一个任务的正式对象

任务内保留以下对象，面板只是它们的不同视图：

1. 输入清单：PRT、DWG、附加技术要求、文件版本与内容指纹。
2. 要求与事实：材料、来料、几何事实、公差、粗糙度、特殊要求及来源。
3. 待确认事项：缺项、冲突、候选、问题答案与确认记录。
4. 工艺方案：基准、装夹、路线、结构化工序表与依赖。
5. 执行批次：冻结快照、工作副本、NX 任务、刀路、NC 与检查结果。
6. 交付版本：实际文件清单、放行记录、适用输入与方案版本。
7. 修订轮次：反馈、影响范围、变更和替代关系。

首期建议一个会话管理一件零件及其修订，避免第二件零件混入当前执行上下文。多零件项目与装配编辑不纳入首期。

## 3. 主布局：画布是底层，面板是工具

### 3.1 桌面默认线框

```text
┌ 产品导航 ┬ 工作台 | 对话 | 轨迹 ───────────────────────────────────────┐
│ 会话     │ 零件名称  修订 R2  当前：工艺规划  待确认 3  [审核方案]      │
│ 记忆库   ├────────────────────────────────────────────────────────────┤
│ 设置     │ [3D 模型] [CAD 图纸] [并排] [文档]       [适配] [扩大画布] │
│          │ ┌ 对象与工序 ┐                    ┌ 检视面板 ─────────────┐ │
│          │ │ 模型层级   │                    │ 选中：面 F000084      │ │
│          │ │ 工位 A     │    模型 / 图纸      │ 属性 | 要求 | 工序    │ │
│          │ │ 10 粗铣    │                    │ 来源与版本            │ │
│          │ │ 20 精铣    │    当前对象高亮     │ [添加到提问]          │ │
│          │ │ 30 钻孔    │                    │ [查看关联要求]        │ │
│          │ └────────────┘                    └───────────────────────┘ │
│          │ 图层 / 坐标轴 / 刀路                  当前工序回放与源码   │
│          ├ Agent ────────────────────────────────────────────────────┤
│          │ 正在核对第 30 工序的刀具与进给；等待 NX 返回结果。          │
│          │ 最新输出：工序表草案 v3  检验要求  待确认事项  [查看对话]    │
│          │ [面 F000084 ×]  输入问题或修改要求……           [发送/停止] │
└──────────┴────────────────────────────────────────────────────────────┘
```

画布保持连续。面板停靠在固定位置，可折叠、调整尺寸，收起后留下小型入口；不让多个漂浮弹窗堆叠。实际可用画布宽度不足时，面板改成互斥抽屉，不能压成一条狭窄的模型区。

| 区域 | 内容与行为 |
| --- | --- |
| 顶部任务栏 | 当前输入与修订、实际阶段、阻塞项、唯一主操作；“阶段”来自正式状态，不来自 Agent 自述 |
| 左面板 | 模型层级、工位和工序。工序按工位分组；勾选控制显示，点击定位当前对象，两者分离 |
| 右面板 | 属性、要求、待确认、工序参数、加工中心配置摘要；优先展示当前对象相关内容 |
| 底部 Agent 面板 | 当前公开回复、真实执行状态、最新产出、输入与对象引用；不展示思考内容 |
| 画布工具 | 视图、投影、图层、适配、选面、模型/图纸切换与并排 |
| 临时展开区 | 工序表、文档、确认向导、NC 源码；关闭后恢复画布相机和选择 |

“加工中心”表示当前方案选用的机床、刀库、后处理器和能力依据，不是机床日排产中心。多个工位或设备在各工序上明确绑定。

### 3.2 显示模式

- **3D 模型**：模型层级、真实面标识、当前工序对象、可信对齐的刀路与坐标轴。
- **CAD 图纸**：图纸页/布局、图层、缩放、局部定位和批注。必须标明原始 DWG 或其转换预览。
- **并排核对**：模型与图纸各有视图控制；已有映射的要素联动高亮，没有映射时允许人工关联，不假装自动对应。
- **文档与工序表**：需要大量阅读或编辑时，占据中央主区域，而不是塞进小浮窗。模型可保留为侧视。

刀路缺少可信工位矩阵时只提供独立 NC 视图，不把轨迹猜测叠加到模型上。回放是近似轨迹展示，不是碰撞仿真、材料去除验证或精确工时。

### 3.3 视觉与可访问性

采用设计软件的稳定工具布局，不采用首页式大卡片、装饰渐变或游戏化任务奖励。

- 复用官方 light/dark/system 主题和语义 token，不新建独立主题系统。桌面直接使用 `--dsw-alias-*`，`/camind` 可经 foundation 映射。
- 浅色参考：画布 `#F3F5F7`、面板 `#FFFFFF`、正文 `#202833`、选择蓝 `#2468D8`、警告 `#946200`、错误 `#B42318`。这是角色参考，实际实现优先使用主题 token 并校验对比度。
- 使用现有系统无衬线字体，正文 14px、辅助信息 12–13px；表格数字用等宽数字，只有 NC 源码使用等宽字体。
- 面板标题、字段和操作左对齐；状态同时有文字与图标，不只靠红绿颜色。
- 模型选择色、工序轨迹色、检查结果色承担不同含义，不复用同一种颜色暗示“已确认”。
- 键盘可定位对象、打开面板和提交问题；Esc 退出临时工具或展开层，不能默默丢弃未保存编辑。画布快捷键不抢输入框按键。
- 首期以桌面为主，按工作台容器宽度响应。窄窗用抽屉与单视图；手机不承诺完整编程体验。

## 4. 接件与动态确认向导

### 4.1 接件不是长表单

空工作台提供两个明确落点：`上传 PRT 模型`、`上传 DWG 图纸`，旁边保留任务输入，例如“先审图”或“完成这件零件的加工包”。

可分批上传，也可从已上传文件中指定对应文件。桌面现有本地路径引用不等于字节上传：可用于预览或分析，但正式接件须显式收集并验证到任务输入快照，不能把路径文本冒充已上传文件。敏感路径、跨会话访问与符号链接边界沿用现有护栏。

上传后先校验格式、可读性、版本、单位与来源。后缀正确不等于内容可用。PRT、DWG 齐全且对应关系经确认之前，不放行方案、不编程；只读分析和补资料仍可进行。

DWG 中若含多个零件或版本，Agent 请求用户指定加工范围。图纸与模型冲突时保留两份证据；用户必须明确差异的处理依据，不能只有一句不带范围的“以图纸为准”。

### 4.2 动态步骤

向导是在画布上展开的工作区，不是覆盖全屏且必须走完才能返回的模态框。阶段可以跳转、暂存与重访。

```text
加工要求 → 来料与材料 → 关键特征 → 方案审核
  已整理      待确认 2       冲突 1       待生成
```

步骤数量和标题可随任务调整；这四组是常见组织方式，不是强制工序顺序。已具备依据的字段自动整理，未涉及的分支不出现。重要声明即使已找到仍进入审核摘要，不因信息完整自动批准。

每个问题包含：

| 内容 | 示例 |
| --- | --- |
| 明确的问题 | “这批来料已经加工六面了吗？” |
| 相关对象 | 当前零件、对应面、来料记录 |
| 已找到的依据 | 用户附件原文、DWG 标注、NX 测量或已确认设备档案 |
| 推荐与理由 | 有来源才给推荐；没有依据写“需要你补充”，不猜毛坯状态 |
| 简单回答 | 接受推荐、选择选项、输入数值、补附件、暂不确定 |
| 后果 | “未确认前，可继续审图，不能放行装夹方案。” |

“接受推荐”记录用户采纳和依据，不把 Agent 推荐变成已测事实。“暂不确定”保持待确认；关键字段不得通过批量接受混入未经确认的值。

### 4.3 减少提问的顺序

先读取输入和企业配置，再调用精确工具补充事实，最后询问仍缺失或冲突的内容。一个问题的答案能解决多个字段时只问一次。用户在对话中明确回答后，Agent 更新同一份结构化草案，不要求在向导重填。

事实分四类显示：**已测事实、文件要求、用户确认、Agent 建议**。来源链接直接定位图纸局部、文件段落或工具结果。已确认事实遇到输入版本变化后须重新核对，不能因旧值仍在表中就默认有效。

## 5. 对象选择与自然语言修改

### 5.1 选择不等于命令

点击零件、面、工序或图纸标注，只改变检视对象。用户点击“添加到提问”后才把对象放进输入区；发送消息才交给 Agent。

引用包含对象类型、稳定标识、文件/方案版本、来源指纹及会话归属。不能只传列表下标、鼠标坐标或“当前面”。图纸矩形截图引用须标明“图纸局部”，不能冒充已识别 CAD 实体。输入区可移除引用，也可同时引用多个面。

源模型换版后旧面编号可能失效：拒绝直接执行，提供重新选择或经过验证的映射。网格拾取用于定位；精确尺寸、干涉及加工几何判断仍由 NX 完成。

### 5.2 修改操作

| 用户动作 | Agent 行为 |
| --- | --- |
| 选面后问“这里怎么加工？” | 查事实、要求和能力，解释方案与依据；不自动创建工序 |
| “这个面精铣到要求尺寸” | 起草加工对象绑定和工序，列出缺项，更新草案 |
| “第 30 工序换一把刀” | 检查刀库与参数，展示受影响项；是否自主应用取决于当前授权范围 |
| “把这些孔一起加工” | 检查工位、可达性和精度依赖，不能因合并更省事就自动拆分必须同装夹的关系 |
| 编辑工序表字段 | 更新同一正式草案，触发校验；不能绕过工具校验直接改执行输入 |
| 拖动工序顺序 | 校验依赖；不合法时解释冲突并保持原顺序 |

草案编辑可撤销。已经执行或交付的版本不可用“撤销”回滚成从未发生；改变它们须开启新方案/修订，保留历史证据。

Agent 的新提醒不抢走用户当前选中对象、相机或文档位置，只显示提示和“查看”。

## 6. Agent 面板与输出组织

底部面板回答三个问题：**现在在做什么、刚得到什么、我需要做什么。**

- 当前响应：公开回答的流式正文，不展示思考内容或内部推理摘要。
- 当前执行：来自 jobs、NX 任务与 runstate 的真实状态，例如排队、运行、等待用户、失败、取消确认中。不虚构百分比或剩余时间。
- 最新产出：事实清单、检验要求、待确认项、工艺路线、工序表、刀具工装清单、检查报告与交付包，点击打开正式对象。
- 当前输入：与官方对话同一个草稿和提交通道，避免两个输入框各持不同内容、重复发送。
- 历史入口：“查看对话”定位对应消息；“查看执行详情”进入轨迹或具体任务详情。

面板不累积完整历史聊天流。当前公开回复可以展开阅读，较长文档有独立阅读视图。任务切换、回合结束或应用重启后，从正式任务状态和会话投影恢复，不显示另一会话的结果。

执行中用户可继续提问、补充信息；改变执行输入的消息应形成待处理变更。若涉及关键变更，先停止后续受影响提交，确认远端在途任务状态，再处理修订。按下“停止”不意味着 NX 已停止；必须区分停止 Agent 生成与取消远端任务。

## 7. 谁做什么：默认让 Agent 工作

| 工作 | Agent 默认负责 | 用户需要做 | 确定性系统负责 |
| --- | --- | --- | --- |
| 接件 | 整理文件、项目字段、版本候选 | 提供 PRT/DWG，确认对应关系 | 格式、归属、指纹、存储边界 |
| 审图读件 | 提取要求、发现冲突、生成事实与检验草案 | 补足无法获得的事实、处理冲突 | NX 测量、几何映射、解析校验 |
| 前期确认 | 合并缺项、生成问题、附依据和推荐 | 回答少量问题、采纳或修改 | 必填、来源与确认状态校验 |
| 工艺规划 | 起草基准装夹、路线、结构化工序和条件分支 | 审核关键方案 | 设备/刀具匹配、参数、依赖和能力校验 |
| 编程 | 在授权内调用工具、监控、分析失败、修复 | 仅处理越界变更或无法自动解决的事项 | 工作副本、NX 独占、任务协议与执行结果 |
| 校验交付 | 整理检查结论、文件清单、设定单与报告 | 确认工艺包放行 | 检查证据、NC 实数对账、完整性和版本冻结 |
| 反馈修订 | 整理反馈、分析影响、提出并执行修订 | 提供实测证据、必要时重新授权 | 旧版保留、影响失效、重新校验和包版本 |

Agent 可以起草检验项目和量具建议，但须依据图纸与实际检验能力。不把“建议使用某量具”写成企业已具备；一次现场试切结论也不自动升级为通用规则。

EDM、WEDM、热处理、手工和外协节点可以出现在正式路线中，没有 NC 的工序仍有执行要求与交接材料。自动执行能力不足必须逐节点标明，不能只显示一个模糊“已完成”。

## 8. 动态工作流：方法、计划与执行证据分开

### 8.1 三层分工

1. **skill：工作方法。** 定义输入要求、如何读取事实、如何提出推荐、必经检查、确认与失败处置。包含适用分支，不写死每个任务的完整 todo。
2. **Agent 行动计划：本次准备做什么。** 根据 prompt 和当前状态增删、调整只读分析与执行任务，解释变化。
3. **正式加工记录：实际上获得了什么、允许做什么。** 要求、工序依赖、冻结快照、授权、run 与检查结果由领域服务保存和校验。

不先建设通用场景市场、流程 DSL 或可视化工作流编辑器。先让同一套对象和护栏支持审图、完整交付、局部修改与反馈修订。

### 8.2 prompt 示例

| 指令 | 工作范围 |
| --- | --- |
| “先帮我审图” | 校验可用输入、读件、整理要求和缺项；不自动编程 |
| “完成这件零件的加工包” | 动态展开接件到交付；在方案与交付点等待确认 |
| “第 30 工序换机床” | 重新校验设备、装夹、刀具、后处理和受影响工序；必要时重新授权 |
| “先别生成 NC，给我路线” | 产出路线与工序草案，到目标即停 |
| “跳过碰撞检查直接交付” | 不删除必要检查；解释当前阻塞，可输出问题材料但不能标为可生产 |

查看阶段不是执行阶段。用户可以回看任何已有对象，但点击导航不能把阶段标为完成或越过前置条件。

### 8.3 DSH 原生 todo 的用途与限制

已核实 `@deepseek-ai/dsh-tool-todo@0.2.0-rc.2`：

- 模型调用 `todo_write` 写入完整列表，整表替换。
- 条目仅有 `content` 和 `pending / in_progress / completed`；没有稳定 ID、依赖、阻塞、版本或证据字段。
- `todos` 会话投影收到 `turn/start` 时重置为空。

因此原生 todo 用于当前回合的行动进度；跨回合任务目标、阶段、阻塞原因、工序依赖和证据保存在正式任务记录中。新回合读取正式记录后再生成适合本回合的 todo，不能把重置解释为加工任务被清空。

todo 完成不是工序完成，也不是放行。用户勾选、Agent 写状态或聊天中说“已完成”，都不能替代 NX 结果和检查证据。正式工序表不复制成另一套可独立编辑的 todo。

## 9. 自主执行与两次主要确认

### 9.1 确认一：审核方案并授权执行

审核页集中显示：输入对应关系、已确认要求、基准与装夹、工位与路线、结构化工序表、实际设备刀具、特殊声明、能力校验、未决项和授权范围。

按钮：**“确认方案并开始编程”**。确认绑定具体输入、方案、企业配置与规则版本，并冻结执行快照。缺少影响执行的事实或证据时不能授权。

授权范围应明确可自动调整的参数和边界，不采用笼统“同意 Agent 做任何事”。在范围内，Agent 可自动重新生成刀路、补后处理、修复确定性校验错误；每次都记录变更和重新检查，不逐操作弹窗。

### 9.2 什么时候重新确认

| 变化 | 处理 |
| --- | --- |
| 已授权约束内的参数调整、补生成 | 自动处理，保留记录并复检 |
| 材料、最终要求、加工对象、基准装夹、加工方法、设备/后处理改变，或授权边界扩大 | 提供影响摘要，回到必要审核，冻结新版本 |
| 工作副本或输入版本改变 | 重核来源和下游依赖；旧确认不能自动继承 |
| 只改报告排版等不影响工艺的内容 | 可自动更新草稿；已交付包仍保留旧版并产出新版 |
| 无法判断变化是否影响安全 | 暂停相关执行，说明缺少的判定依据 |

### 9.3 确认二：放行工艺包

审核实际 NC、加工副本、设定/装夹说明、工序表、检查报告、检验与交接要求、条件附件及输入归档。按适用内容核对，不适用项明确写出依据。

状态与动作必须区分：

- **草稿**：尚未放行。
- **问题包**：有未决项，可以导出用于排障，但不得显示为可生产，也不能使用“放行交付”按钮。
- **已放行工艺包**：必要检查通过、适用材料齐全、用户完成确认。
- **已被替代**：保留历史文件，当前任务提示使用新版；不能保证现场已经撤回旧文件。

现有“检查未全过也可出包”的行为只能对应问题包。用户签字不能把未解决的执行相关问题转换成“检查通过”。

## 10. 正式状态、修订与恢复

### 10.1 状态不是一条聊天进度条

任务可以处于 `输入待补 / 分析中 / 待确认 / 方案草稿 / 待授权 / 执行中 / 检查中 / 待交付确认 / 已放行 / 修订中 / 阻塞`。这些是常用状态，不要求每个 prompt 遍历全部状态。

各对象另有版本与有效性：草稿、已确认、已冻结、执行结果、已失效。正式任务记录通过真实文件和工具结果推导阶段；Agent 不能直接宣告“已放行”。

结构化工序至少保留：稳定工序 ID、顺序与类型、加工对象、基准装夹、工位与设备、刀具/电极、参数、余量与目标尺寸、检验项、依赖、执行方式、是否生成程序、来源、状态与检查证据。

### 10.2 现场反馈开启修订

```text
已放行 R1 → 提交反馈 → 整理证据与影响 → R2 草案
         → 必要方案确认 → 编程与重新校验 → 放行 R2
```

“孔偏小”不能自动判成刀补错误。先整理实测值、量具与条件、现场装夹、所用 NC 版本和材料状态；缺信息时询问。结果可能是工艺修订、程序问题、现场执行问题或证据不足。

同一会话保存多次修订，每次可有多个执行 run。未受影响结果只有在依赖与指纹验证通过后才可复用，并显示来源版本；不能因为上次工序是 ok 就跳过重算。

旧包不可覆盖。新包明确替代范围和旧版处置提醒；软件不声称能够撤销已经下载、传给设备或现场执行的 NC。

### 10.3 重启、失败与并发

- 应用重启后恢复正式草案、确认、run 和交付状态，不能只靠浏览器局部 store。
- 一个任务的执行输入只允许一个有效写入版本；冲突更新拒绝或提示重新加载。
- NX 仍是共享串行资源，显示真实排队与占用。不因 Agent 多任务计划而并行写同一 NX 会话。
- 超时或取消不明确时先查询远端状态，不盲目重复有副作用的操作。
- 工具拒绝、空刀路、参数冲突、NC 缺失都定位到对象，显示失败依据、已保留结果和下一步。

## 11. 与现有实现的衔接

### 11.1 已核实事实与缺口

| 现有基础 | 新方案需要补齐 |
| --- | --- |
| `ui-workbench` 右侧页签已有输入、交付物、加工时间线 | 升为 `conversation.view` 一级工作台，迁移业务内容，不保留重复右栏 |
| `ui-preview` 有通用预览与会话文件引用服务 | 常用文件在工作台打开；保留引用与路径安全边界，预览目标改为会话隔离 |
| `ui-model-viewer` 已有模型、NC、选面、回放与可信联合显示 | 暴露工作台对象引用与选择契约；不重复实现 WebGL 查看器 |
| DSH 支持 `conversation.view` 和会话 store 的 `setView` | 标签排序可配置，但默认解析仍回退 chat；默认工作台需要独立适配，不能只改 order |
| 现有切页桥使用内部 `hostFace().storeOf()` | 隔离适配风险并做升级回归；不假定稳定公开接口 |
| 现有 `cam_plan / cam_run / cam_deliver` 与闸门 | 扩展正式方案/授权/修订契约；现有逐 run ask 不能仅靠隐藏 UI 变成持续授权 |
| 现有 runstate 和只读查询可呈现真实过程 | 复用 run 数据；增加跨回合正式任务状态，不重新发送自定义 `cam/*` 会话事件 |
| 原生 todo 有当前回合行动列表 | 与正式任务记录分工，补跨回合恢复与阻塞投影 |
| 现有 skill 是固定四工具流程，明确暂不支持 2D 解析 | 更新为 prompt 驱动范围与动态确认，不先宣称 DWG 已可阅读 |

普通 `cam_run` 尚缺完整工位矩阵回读，无法自动生成可信联合预览证据。现有查看器不提供生产级碰撞、过切或残料验证。检查覆盖率不足时必须明确说明，不能将 NC 对账 overall=ok 升格为全部生产校验通过。

DWG 展示、语义提取、尺寸/公差读取和模型映射是不同能力。具体解析/转换服务、部署、许可证与数据出域方式需技术验证；优先受控本地转换，不能未经同意上传客户图纸到第三方。解析失败保持阻塞，PDF/截图可辅助阅读但不替代必须归档的 DWG。

### 11.2 最小职责划分

- **ui-workbench**：主工作台、面板与任务对象交互；同一份逻辑服务桌面、官方 Web 和 `/camind`。
- **ui-model-viewer**：3D、刀路、选择和显示能力；精确计算仍交 NX。
- **ui-preview / previewFiles**：会话授权文件解析、通用文档预览与引用。
- **tool-cam**：正式加工数据、版本、授权、执行与校验；前端不写 run 文件绕过领域服务。
- **tool-upload**：正式输入收集与上传边界；桌面本地引用转输入快照须明确验证。
- **skill**：方法和路由，不承担事务、安全闸门或持久化真源。
- **ui-shell**：装载与路由；移除 `/camind` 重复工作台列，不把新业务只做在浏览器壳。

主聊天提交通道和投影适配在实现前核实官方契约，不通过 DOM 抓取聊天内容或另建一套 LLM 请求。隐藏思考只改变面板呈现，不意味着删除会话原有记录。

### 11.3 与旧设计的关系

本方案是此次用户需求的交互基线，与 [旧版 CAM 作业面设计](cam-job-interaction-design.md) 有以下差异：

- 不引入多角色和厂内 Agent 等级配置。
- 以模型/图纸画布为稳定中心，文档和工序表按需展开，不固定阶段轮流替换全部舞台。
- Agent 面板展示当前响应与结果，完整历史只在对话标签。
- 不先建设通用场景包阶段运行时；由 skill、动态计划和正式对象支撑所需流程。
- 交付后原任务内修订，不要求克隆为另一个会话。
- 有执行相关未决项只能导出问题包，不能人工签字标为可生产。

本文不修改旧文档、现有 skill 或工具契约；进入实施时须一并同步对应行为，不能只替换界面。

## 12. 分期实施

### 阶段一：主入口与上下文交互

升工作台为一级标签；嵌入既有模型/NC 查看器和文档预览；加入当前 Agent 响应面板与共用输入；实现面/工序引用；移除重复工作台。保留现有执行闸门，明确尚未具备的能力。

交付标准：桌面真实工作台可连续查看、选面、提问、打开产出；不重复提交、不串会话、不误报完成。

### 阶段二：完整接件、确认与正式方案

验证 DWG 阅读链路；实现双文件接件、版本对应、来源分类、动态确认、跨回合任务记录和结构化工序草案；更新 skill。DWG 不可读、事实缺失或正式规划表达不足时，不宣传完整自主交付。

交付标准：Agent 从真实输入生成事实、要求、问题、推荐和路线；用户只处理必要确认，修改能触发正确失效与校验。

### 阶段三：授权执行、完整检查与修订交付

实现范围化授权、授权内自主修复、关键变更重新确认、交付版本与问题包区分；补齐常规执行的工位回读及必要检查证据；加入现场反馈修订闭环。

交付标准：经授权可连续执行，不能越界或把显示当仿真；旧包保留、新包可追溯，缺必要证据不能放行。

EDM/WEDM 等分支逐项接入，每项必须具备输入、能力依据、工具结果或外部交接要求；不因路线里出现节点名称就宣称自动完成。

## 13. 验收场景

以完整重启后的真实 Camind 桌面应用为主；浏览器与离线自检辅助。结束清理自起调试实例，保留用户原有进程。

1. 新加工任务默认工作台；主动切对话后新进度不抢页，刷新/重开恢复合理选择。
2. 只提供 PRT 或 DWG 可分析和聊天，不能方案放行或编程；文件坏、版本冲突有明确缺项。
3. 桌面本地引用预览可用，但未收集到正式输入快照不能伪装为已上传。
4. Agent 已读到的字段不重复问；无依据不生成事实值，采纳推荐有确认记录。
5. 点面不发送、不执行；添加引用后发送进入同一官方会话，旧版面引用被拒绝。
6. 画布、图纸、工序和文档可切换，相机与编辑位置合理保留；提醒不抢选择。
7. Agent 面板无思考内容，只有公开回复、真实状态和输出；完整历史可定位。
8. 新回合 todo 投影重置不丢正式任务；重启能恢复草案、阻塞、授权与 run。
9. “先审图”不自动编程；“全流程”可生成动态计划，但 prompt 不能删除必要检查。
10. 授权内可连续修复；越界变更停止受影响提交并重新确认，不能只隐藏审批卡。
11. 取消、超时与 NX 未知状态不盲目重跑；已生成结果和失败记录不丢失。
12. 没有真实工位证据禁用叠加；纯 NC 可查看，回放不标为生产仿真通过。
13. 空刀路、NC 缺失或适用检查未通过只能导出问题包，不能放行可生产包。
14. 现场反馈可开启 R2，受影响结果正确失效，旧包未覆盖，新包有替代说明。
15. 窄工作台容器、浅深主题、键盘操作、输入焦点与大文件显示稳定；会话切换不串文件或结果。

## 14. 明确不做与待验证项

首期不做多角色协作、MES、现场合格判定、任意浮窗布局编辑器、装配编辑、通用工作流市场，也不从零重写查看器与聊天系统。

落地前需验证：DWG 读取/转换与许可证；官方输入与流式回复投影契约；默认标签与空会话挂载；跨回合任务保存；范围化授权与取消；NX 精确几何关联、工位回读及必要生产检查能力。

当前核查依据为本仓库工作台、预览、查看器文档、加工 skill，以及本机 npm 缓存中的 DSH 0.2.0-rc.2 conversation 与 todo 实现。未开展新的运行时 UI、NX 或生产加工验收，也未据此对 Codex、Claude、Pi、Cursor 做横向产品结论。
