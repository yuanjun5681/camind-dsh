# 正式加工任务记录（当前实现）

接件、来源、确认、工序、方案授权、执行与反馈修订从对话中分离保存。新编程批次强制绑定正式 PRT/DWG 和方案授权；历史批次保留原执行审批。当前生产证据不足时只出问题包，生产放行明确拒绝。

## 存储与工具

`$DSH_HOME/cam-tasks/<session>/task.json` 保存单会话任务、单调递增 version、修订、输入 SHA、要求、问题、用户回答、工序及审计。写入使用 OS 目录锁和临时文件原子替换，旧 version 返回冲突。进程退出后的有效 PID 锁可恢复；缺少 PID 的异常锁需人工核实后清理，不自动抢占。

输入复制为 SHA 命名的只读业务快照，原件不覆盖。PRT/DWG 引用来自当前会话预览边界；headless 使用当前会话上传清单。`task-input://<revision>/prt|dwg` 提供当前或已归档修订的只读引用。执行相关敏感操作、引用序列化会重新核对原件与快照 SHA。历史对象保留历史含义；只有最新用户请求的引用参与 pre-step 校验。

- `cam_task`：read / collect / update。写操作需 version；不开放用户回答、签字和执行结果字段。
- `read_drawing`：分页、检索或按实体句柄读取已归档 DWG 标注；绑定 DWG SHA。尺寸属性不是 NX 实测。
- `cam_survey`：内容寻址上传、NX 队列与未保存模型检查；成功后将对应 PRT 的事实保存至正式任务。

图纸来源要求引用当前 SHA、稳定句柄与可核验原文；建议必须标为 recommendation。用户确认经独立 UI 路径保存。输入换版撤销确认/授权并标记要求失效；PRT 字节未变时保留已有 NX 事实。工序 ID 不重复，依赖只能指向前置工序，避免重排成环。

## 审图确认与只读加工要求清单

问题按 `review / planning / system` 区分范围，审图向导只处理当前审图问题和双文件对应关系。逐题回答与最后整体确认是两个动作：“使用建议”或自定义意见保存回答，“暂不确定”保存未决；回答本身不代表审图完成。用户最后通过 `finish-review` 提交当前 version、审图 fingerprint 和 `requirement_ids`，服务重新核验前置条件。

`requirementDraft(task)` 从当前有效来源的要求和已解决审图回答生成展示清单：排除旧 DWG SHA、失效条目、未采纳建议及重复身份字段，保留加工数值、单位与有意义的说明；待核对/待提供内容归入补充约定。它是确定性展示投影，不调用模型补写事实。

最终确认将用户勾选条目、schema 和草案指纹持久保存到 `review_confirmation.requirement_summary`。`requirement_summary` 投影返回 draft、fingerprint、status 与有效 confirmed 快照：只有审图完成且草案指纹匹配时才是 confirmed；不存在快照为 unconfirmed，内容不匹配为 stale。右侧面板只读展示有效 confirmed.items，与汇总所选清单一致。

旧调用未提交 `requirement_ids` 的审图完成记录不自动生成清单确认。历史任务可从顶栏“确认加工要求”直接进入汇总，复用有效回答；未确认或失效时不把原始提取列表当作已确认要求。输入、要求、问题或回答变更后重新校验，旧快照不作为当前结论展示。清单确认不替代方案授权、NX 测量或生产放行。

## 工序编辑与方案确认

工作台工序表支持编辑名称、工位、模板、刀具引用、转速/进给、部分切削参数、前置依赖和检验要求，以及重排/删除。保存使用打开编辑器时的 version；后台修改导致冲突时保留当前输入，不覆盖新版。用户修改单独审计，并撤销旧授权。

方案审核固定展示打开时的输入、要求、装夹、机床与工序快照；用户勾选确认后保存指纹。缺少双文件或实测事实时入口不可用。自主调整默认关闭，只允许从零建工序已有转速/进给的明确范围；当前参数必须在区间内，执行提案不得通过删除该参数绕过核验。模板复制不允许此类调整授权。确认时再次核验几何包版本。

cam_plan 使用当前正式快照、绑定冻结机床/后处理/初始化/工序，按 run 隔离输出。cam_run 在每次 NX 提交前重新核验授权，记录开始/结束与停止后不再提交；范围内参数修复建新批次，关键变更重新审核。JSON 对象键顺序不影响方案语义核验，数组顺序仍严格冻结。参数编辑不代表 NX 已应用参数，方案确认不是生产放行。

## 本地 DWG

宿主需要 GNU LibreDWG 的 `dwgread` / `dwg2SVG`（本机 0.14）。处理使用 execFile，不调用 shell；限制输入、输出与运行时间，不发送到新增第三方服务。未知代理实体、不可读取标注或单位不明保留阻塞。

SVG 是部分二维实体预览，不是完整 CAD 或测量引擎。客户端只保留 SVG 图形/文字白名单，移除脚本、外链、事件及外部对象；原始尺寸、格式和视图关系仍须核对原图。图纸标注与工序可显式加入原生草稿，保留已有文字和其他引用；插入不是发送或授权。

## 桌面验收

`node tool-cam/selfcheck-tasks.mjs` 检查文件系统、CAS、源核验、锁、工序依赖、来源及修订；另覆盖清单过滤、显式选中冻结、失效隐藏、旧版记录不自动确认和重启恢复。NX 事实为明确的测试 fixture，不是生产证据。

真实桌面完整重启后：

```sh
CAMIND_PLAYWRIGHT_PATH=<playwright-core> node ui-workbench/acceptance-desktop.mjs
CAMIND_PLAYWRIGHT_PATH=<playwright-core> node ui-workbench/acceptance-task-desktop.mjs
```

第二项使用实际 DWG，实测 612 个标注、SVG 真实渲染、原生标注引用保留文字、单 DWG 拒绝授权、原件变更拒绝引用及 SVG 清洗；另使用明确的验收草案验证真实工序编辑落盘、用户审计、授权撤销与缺件时审核入口禁用，pageerrors=0。只发送一个无文件内容的数字回复请求，不执行 NX。临时源文件清理，任务快照与截图仅保留在私有 `.dsh/`。

## 不可覆盖交付与反馈

cam_deliver 经过独立打包确认，先写临时目录，再原子冻结 delivery/；已存在的包拒绝覆盖。manifest 包含文件 SHA、方案来源、证据缺口及简单 NC 命令回读。ASCII 的 S/F/T 命令存在性只是局部核对，不是完整仿真或机床装载证明。

工作台核验放行条件后明确显示缺口。反馈建立同任务下一修订，保留旧输入/方案/包，撤销授权、清空旧工序与装夹确认；反馈本身不提交 NX。

## 真实 NX 完整链路验收

以下命令使用当前配置的真实 NX 服务，仅对独立工作副本编一道验收开粗，自动签署明确标为测试假设的范围；不是全件生产方案。运行前需完整启动桌面并保证原生窗口可用、编辑器无草稿、NX 队列空闲且无未保存模型。CAMIND_ACCEPTANCE_POST 必须是已核实的注册名，不是机床档案展示名。

```sh
CAMIND_ACCEPTANCE_FULL=1 CAMIND_ACCEPTANCE_POST=<已注册后处理器精确名> \
  CAMIND_PLAYWRIGHT_PATH=<playwright-core> node ui-workbench/acceptance-nx-desktop.mjs
```

脚本归档指定 PRT/DWG 的私有副本、调用原生 Agent 读件审图、生成预览、记录测试假设、保存工序、界面审核、执行开粗/后处理/NC 对账、确认打包、核验放行拒绝并反馈修订。默认不设 FULL 时只做读件审图。原件 SHA 前后必须一致；证据/输入副本仅在 .dsh/workbench-acceptance/，不提交。失败可见并立即断言，不把模型的口头“完成”当成功。

2026-10-13 真实链路已走通：源件 1 实体、231 面、120×187×30.5 mm，DWG 612 标注；单次开粗回收 1 个 NC，S8000/F2400 回读匹配。NC T01 与冻结机床刀位 T3 不一致，已写入 manifest/问题报告，未升级为生产就绪。一键完整链路（含尾段修订）由 acceptance-nx-desktop.mjs 验证，另由 acceptance-completion-desktop.mjs 独立复核交付和修订，页面错误为 0，R2 撤销授权，R1 包 SHA 不变。旧脚本重复 alert 选择器已按对象检视区定位修正。

验收中发现并修复 SDK jobs owner/result 契约、NX 父组名、精确后处理名、inspection 字段提示和对象键顺序造成的误拒绝。预览导出成功后仅关闭自建 UUID 标记副本，避免导出临时修改阻塞后续读件；加工检查可能留下自建工作副本未保存状态，继续任务前核实并处理，不能自动丢弃用户模型。

## 仍不能证明的生产条件

NX cam_gouge_check 总体 PASS 可来自部分工序；没有真实刀柄时碰撞零值没有对应证明；也不覆盖完整夹具与残料验证。cam_verify_probe 是 API 发现，cam_ipw_probe 是试验性 IPW 探针。模板复制不应用草案转速/进给，相关自主调整明确拒绝。

本次只读前 20 条图纸标注，只编一道验收工序；材料、毛坯、装夹为试验假设，颜色公差/全件工艺与工位坐标未验证，机床后处理资格为 DRAFT、刀具实测未知。放行服务目前只有拒绝路径，没有伪造的生产放行正路径。

前端依赖已显式升级并通过 override 统一 katex 到修复版；npm audit（含开发依赖）与 npm audit --omit=dev 均为 0 项，未使用 --force。
