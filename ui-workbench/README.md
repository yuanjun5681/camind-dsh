# 加工工作台

`camind-ui-workbench` 注册一级会话标签“工作台”，排在“对话”“轨迹”前，在真实桌面、官方 Web 与 `/camind` 共享实现。目标设计见 [交互方案](../docs/cam-workbench-interaction-design.md)。

## 首期已实现

- 顶部合并文件标题、模型/图纸入口和新窗口打开；右侧以 48px 图标栏统一提供任务资料入口（名称提示、选中态及键盘可访问名称）；输入、交付物、加工记录在右侧按需展开，既有 run 查询和下载不变。
- 文件、模型、NC 和可信联合预览通过 `filePreview.View` 嵌入中央画布；点击输入或产出不再跳到独立预览标签。
- 预览目标按会话隔离，点击文件会返回画布；切换工作台内容不卸载正在查看的模型。会话里出现可用 PRT 时自动设为预览目标并切到模型画布：首个自动显示，之后每个新出现的 PRT 再自动切换一次，同一文件重复轮询不打扰；PRT 缺几何包时由 ui-model-viewer 自动开始生成。
- 最新活动订阅官方 `target('chat').legacy`：生成时由紧凑插件显示当前轮次最新工具活动或公开回复行，结束后恢复原生 Composer，不常驻历史回复，不显示 reasoning。
- 选面后明确点击“添加到提问”，将文件/几何版本和面编号插入原生可移除引用 chip，保留已有草稿，不自动发送。发送及当前请求进入 Agent 步骤时核验版本；历史引用不会封死新版本讨论。
- 交付物读取官方轮次的 `deliverables` 数据与 CAM run 的真实文件清单；文件存在不代表已获生产放行。
- 没有保存标签偏好、且存在可用 PRT 时默认工作台；保留用户主动选择的标签。纯咨询不自动切换。空白会话仍沿用官方首页，一级工作台在会话有内容后显示。
- 移除右栏工作台注册和 `/camind` 重复列。打开新工作台时关闭当前旧 `cam-workbench` 页并折叠右栏，其他右栏内容不删除。

## 接件审图工作区

工作台内使用稳定模型画布与右侧资料入口，不再通过业务 TAB 切换。正式 PRT 自动恢复为主预览；图纸入口打开本地转换预览与可搜索标注。底部通过独立 ui-compact-composer 插件将原生 composer 压缩为单行输入和提交按钮，生成时显示状态与当前轮次最新公开输出行；输入框完全浮在当前模型视区底部，画布不为浮层缩短；打开资料面板后浮层跟随模型视区居中。

审图问题标记为 `scope: review`，规划问题为 `planning`，工具状态为 `system`。分析结束时临时展开逐题审图向导，从首个未确认问题继续；顶部显示题号、处理进度及已确认数，底部步骤导航可跳转回看。每题提供使用建议、暂不确定和其他建议或补充；建议与暂不确定点击即保存，成功后自动下一题，自定义意见提交后前进。失败保留当前题和草稿；暂不确定仍为未决。最后汇总回看并单独点击完成确认；“保存并稍后继续”保留未决。完成必须由用户通过 `finish-review` 路由提交当前版本和审图指纹，输入/要求/问题变化使确认失效。完成后关闭向导与继续入口，回到模型；汇总页展示待纳入清单，允许取消条目，整体核对后冻结；右侧加工要求仅只读显示这份清单，不展示问答、原文证据或修改入口。旧版确认需从顶栏“确认加工要求”核对清单，不自动沿用。重启恢复确认状态和正式模型。没有 scope 的历史问题保守按 review 处理，不能自动消除旧未决。

审图完成与方案授权分别核验。机床、工序、NX 事实、几何、毛坯、基准和装夹仍由编程门禁验证；缺生产检查证据仍不可生产放行。DWG 展示是部分实体预览，适配渲染实体边界不代表精确量测。当前没有生产级碰撞仿真。

工序方案里的规划确认独立于审图向导；材料、毛坯、基准、装夹四字段预填建议，并归并同字段冲突，用户一次保存确认。已确认值与 Agent 重复建议相同时保留确认，实质改变时新增明确冲突；失败保留草稿，执行期间禁止修改。工作台渲染失败显示重试入口，不再沿用上游空白错误节点。方案审核以工作台内独立弹窗展示人类可读的工序表、冻结输入版本和本次修改；确认后工作台可点“生成 NC”，结束后点“打包问题包”，通过原生输入服务提交 Agent 请求，已有草稿或执行中的请求不会被覆盖。审批卡也在工作台完成。正式批次在 NC 及检查结束后调用 `/cam_finalize_work_copy` 保存并单件关闭自己的 output 工作副本；只接受保存核验、IsModified=false 与关闭回读全部成功。接口缺失或失败时记录“副本待处理”及具体文件，NC 生成结果不被改成失败，不调用旧关闭接口降级，不自动处理历史 input 副本。顶部阶段区分“已授权，待生成 NC”“NC 已生成，待打包”“问题包已交付，未放行”，生产检查不与 NC 生成结果混淆。审批卡定位使用稳定画布范围，模型视区折叠到零尺寸时输入区域也回退到画布。

## 验证

```sh
node ui-workbench/selfcheck.mjs
node ui-compact-composer/selfcheck.mjs
node tool-cam/selfcheck-tasks.mjs
node ui-preview/selfcheck.mjs
node ui-model-viewer/build.mjs
node ui-model-viewer/selfcheck.mjs
npm --prefix ui-shell run build
```

真实桌面完整重启后，使用已有会话、已有同源模型缓存，不调用模型/NX、不上传文件：

```sh
# 调试桌面由操作者以项目 DSH_HOME 启动，端口 9236。
sh ./scripts/desktop.sh --remote-debugging-port=9236
CAMIND_PLAYWRIGHT_PATH=/path/to/playwright-core node ui-workbench/acceptance-desktop.mjs
```

验收覆盖标签排序、旧右栏迁移、缓存模型、侧边资料、输入/交付/加工、回对话不被轮询抢页、原生输入可见及选面引用保留草稿。必须使用空草稿，不发送提问。

真实回复链路另用以下脚本：**会新建独立验收会话并发送一次仅输出数字的模型请求**，记录公开文本的流式更新，检查持久日志中工具调用数为零，并切回原会话。

```sh
CAMIND_PLAYWRIGHT_PATH=/path/to/playwright-core node ui-workbench/acceptance-response-desktop.mjs
```

此项需要可用模型与 `zstd` 命令；报告仅写入私有数据目录。自检使用真实的官方聊天目标与轮次数据结构，覆盖公开流式/终态、原生 chip、保留草稿、失效及跨会话拒绝。截图与报告在 `$DSH_HOME/workbench-acceptance/`，不提交私有数据。自检另覆盖会话预览隔离、无效/缺失文件不抢页、思考文本不泄入当前响应面板。

结束后退出自己启动的桌面及子服务，不停止用户原有 Web 进程。
